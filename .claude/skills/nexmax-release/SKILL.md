description: このアプリのデプロイ・リリース作業のときに必ず発火。「STGに上げて」「ステージングに反映」「本番に出して」「本番OK」「確認URLを更新」「デプロイして」「閉じて」「マージして」と言われたときに使う。クライアント方式（ユーザーはPR・マージをしない）で main統合 → STG → 確認依頼 → 「本番OK」→ 本番反映まで、輪を閉じて進める。
---

手順の正は `docs/deploy.md` §0（特に **§0.6 本番リリースの輪**）と AGENTS.md「統合とデプロイ」。
**作業前に両方を Read すること。**

骨子（詳細は上記2文書）:

1. **作業中の確認** → `npm run cf:branch`（自分専用URL。stagingに上げない）
2. **出す前の検収（教材・会話UIを変えたとき）** → 作った本人ではない目（別セッション/
   エージェント）が、設計01 §4 失敗カタログ＋意地悪条件（文の途中で5秒止まる・声をつながない・
   言い直す・回線が切れる）で通しプレイしてから統合する（2026-08-19 導入・願い #97）
3. **リリース** → 先に `origin/main` を取り込む → AI が PR 作成 → CI green で AI がマージ →
   **STG は main への push で自動反映**（Actions「デプロイ」。鍵は GitHub 側。
   手元で `cf:staging` を叩かない）。STG の `/api/version` が main の SHA になったことを確認
4. **確認依頼（ここで輪を閉じる）** → 報告は「URL＋操作＋見るポイント＋**OKの返しかた
   （『本番OK』と一言）**」の4点。チャットは流れるので、**マイタスクボードの
   「STG確認 → 本番OK」タスク（1件を使い回す）にも確認待ちを追記**する（スキル
   `managing-my-tasks`）。`npm run handoff` の「■ 本番待ち」にも自動で出る
5. **本番** → ユーザーの「本番OK」を確認したセッションが
   `gh workflow run deploy.yml -f target=production` → `gh run watch` で完走 →
   本番 `/api/version` が main の SHA と一致 → タスクを閉じて報告。
   OK 後に統合が増えていたら、増えたぶんも一覧にして報告する
6. 反映後は**主要ページの生存確認**をし、変えていない画面が変わっていないことも確認
   （= 引き算検証）
