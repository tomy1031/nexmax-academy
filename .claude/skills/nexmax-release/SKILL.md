手順の正は `docs/deploy.md` §0（特に **§0.6 リリースの輪**）と AGENTS.md「統合とデプロイ」、
そして `docs/constraints.md`。**作業前に3つとも Read すること。**

> **いちばん間違えやすいところ その1**: 本番は **「本番OK」を待たない**。
> 2026-08-21「これチェックする時間がないため、対応終わったら速攻でデプロイしてください」で
> 待つのをやめた（`docs/constraints.md` 製品の制約）。待っていたころは STG が1日14回
> 更新されたのに本番は2回で、直したものが何日も学習者に届かなかった。
> **ユーザーに「本番OK と返してください」と求めるのは、この決まりに反する。**
>
> **いちばん間違えやすいところ その2（2026-08-27〜）**: マージ先は **`main` ではなく
> `integration`**。STG に載るのは `integration` で、本番に載るのが `main`。
> `main` へ直接マージしても **STG は変わらない**。
> そして **本番は授業の前に自動で出る**ので、ふだんは `target=production` を回さない。
> ——これは「本番OK 待ち」の復活ではない。**待つ相手が人ではなく時刻**になっただけで、
> 上の 2026-08-21 の決定と矛盾しない。

骨子（詳細は上記の文書）:

1. **作業中の確認** → `npm run cf:branch`（自分専用URL。stagingに上げない）
2. **出す前の検収（教材・会話UIを変えたとき）** → 作った本人ではない目（別セッション/
   エージェント）が、設計01 §4 失敗カタログ＋意地悪条件（文の途中で5秒止まる・声をつながない・
   言い直す・回線が切れる）で通しプレイしてから統合する（2026-08-19 導入・願い #97）
3. **統合** → 先に `origin/integration` を取り込む → AI が **`integration` 宛て**に PR 作成 →
   CI green で AI がマージ → **STG は `integration` への push で自動反映**
   （Actions「デプロイ」。鍵は GitHub 側。手元で `cf:staging` を叩かない）。
   STG の `/api/version` が `origin/integration` の SHA になったことを確認
4. **本番（ふだんは何もしない）** → 授業のある **火・水・金 17:05 ICT** に、ワークフローが
   `integration` → `main` を早送りして自動で出す（授業は 17:30。ビルドから検証まで6〜10分）。

   **緊急のときだけ手で出す**（バグ・授業当日の事故）。`main` から切って `main` へ PR →
   CI green → マージ → 下を回す → **`main` を `integration` へ戻しマージ**（忘れると
   次の昇格が「早送りできません」で止まる）。`gh` が無いセッションでは GitHub MCP の
   `actions_run_trigger`（`run_workflow` / `deploy.yml` / ref=main / inputs `{target: production}`）。

   ```bash
   gh workflow run deploy.yml -f target=production   # gh があるとき
   ```

   ワークフロー自身が `/api/version` を突き合わせて、載っていなければ落ちる。
5. **報告** → 「URL＋操作＋見るポイント」は これまでどおり添える。ただし
   **OKを求めない**（見るのはユーザーの都合のよいときでよい）。
   「本番待ち」のタスクは作らない・残さない（時刻で出るので、待ちではない）
6. 反映後は**主要ページの生存確認**をし、変えていない画面が変わっていないことも確認
   （= 引き算検証）

## 見るURLを取りちがえない

ユーザーが「変わってない」と言ったら、**まずどのURLを見たかを確かめる**
（2026-08-22 に実際に起きた。本番だけ古いまま置いていた）。

| | URL | 載るもの | 更新のされかた |
| --- | --- | --- | --- |
| 本番 | `academy.nexmax.workers.dev` | `main` | **火・水・金 17:05 ICT に自動**。緊急だけ手動（手順4） |
| STG | `staging-academy.nexmax.workers.dev` | `integration` | `integration` への push で自動 |
| ブランチ | `<ブランチ名>-academy.nexmax.workers.dev` | 作業ブランチ | `npm run cf:branch` |

**STG は作りおきゼロで出る**（KV書き込み 0件にしたため）。各ページ初回だけ 1〜2秒 遅いのは
仕様どおりで、不具合ではない。負荷の確認は**本番に向けて**行う（docs/deploy.md §0.6 末尾）。

どこが何を載せているかは `/api/version` の `sha` で分かる（ビルド時のコミット）。
**ログインなしで中身まで見たいときは `/api/<でたらめな名前>`** を開く
（middleware は `/api/` を通すので、404画面がそのまま見える）。
