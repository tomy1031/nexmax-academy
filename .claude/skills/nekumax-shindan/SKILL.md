# ネクマックス診断のコンテンツを直す

学習者はカンボジアのIT専攻学生。日本語学習歴1年、N4学習中〜N4合格が中心で、N3もいる。
**読めない文は存在しないのと同じ**なので、意味より先に読めるかを見る。

## 0. まず読む

コードに触る前に必ず開くこと。ここに書いてある判断はすべて理由つきで残してある。

| ファイル | 何が書いてあるか |
|---|---|
| `docs/design/07_性格タイプ設計_MBTI16.md` | 診断の全体。§2 文言のきまり／§2.5 語彙メモ／§3 20問／§10 文言チェック |
| `docs/design/01_理解設計ガイド.md` | 13原則と失敗カタログ。**P8・P11・失敗カタログ1** は診断に直接効く |
| `docs/design/08_授業サポート表示設計.md` | 教師向け表示。生成しない理由と、書いてよい文の範囲 |

## 1. どこに何があるか

| 直したいもの | ファイル |
|---|---|
| 16人の呼び名・ひとこと・4行の説明・チーム役割 | `src/content/personality.ts` の `PERSONALITY_TYPES` |
| 4つの組の名前・とくいなこと | 同 `PERSONALITY_FAMILIES` |
| 20問の設問と選択肢（やさしい日本語／日本語／English） | 同 `PERSONALITY_QUESTIONS` |
| ふりがなの読み辞書 | 同 `PERSONALITY_RESULT_READINGS` と各設問の `readings` |
| 語彙メモ（意味＋英語） | `src/content/glossary.ts` |
| 相性の説明文 | `src/content/personality.ts` の `getCompatibility` 周辺 |

**表示側は触らなくてよい。** 台帳を直せば結果画面・図鑑（`/nekumax`）・管理画面に同時に反映される。

## 2. 直すときの規律

### 絶対にやらないこと

1. **4文字コード（ISTJ・ENFP など）を学習者にも教師にも見せない。** 診断はネクマックスの世界で完結させる。台帳の文言に混ざっていないかは `tests/personality.test.ts` が検査する
2. **「不正解」「間違い」「ダメ」を使わない**（CIで落ちる）
3. **ルビHTMLを手書きしない。** 読み辞書に登録して合成させる
4. **むずかしい語をひらがなに開かない。** 開いても意味は出ない。**漢字＋ふりがな＋語彙メモ**にする
5. **擬態語・畳語副詞を使わない**（きちんと・はっきり・じっくり・つぎつぎ・さっと・まっすぐ）。読めても意味が出ないので、ふりがなでも語彙メモでも救えない
6. **交ぜ書きを使わない**（手じゅん・目ひょう・てい案）。読み辞書に登録できない

### 必ずやること

- **ひとことは述語で終える**（「〜します」）。体言止めは「文が途中で切れている＝自分が読めていない」と読まれる
- **1文の未知語は1語まで。** とくに4行目（結果画面で最も読ませたい一文）
- **Ⓐ と Ⓑ の難しさをそろえる。** 片方だけ難しいと、意味ではなく読みやすさで選ばれて軸が偏る
- **同じ画面の中で表記をゆらさない**（きもち／かんがえる／気が つく／提案）
- 職場語は**平易語に置き換えない**。語彙メモで支える（01ガイド R6-1）

### 読み辞書を足すときの罠

`RubyText` は同じ位置で一致した語のうち**配列で先に出たほうを採る**。
「手」より後ろに「手順」を置くと「順」が裸で残る。**新しい熟語は配列の先頭に足す。**
この不変条件は `tests/glossary.test.ts` の「短い語が長い語を食べていない」で固定してある。

## 3. 手順

```
① 直す前に、いま何が書いてあるかを読む（該当の台帳を全部）
② 直す
③ 読み辞書と語彙メモの追随を確認する
   - 漢字を増やしたら PERSONALITY_RESULT_READINGS に読みがあるか
   - むずかしい語を増やしたら glossary.ts に意味と英語があるか
④ 検査を通す
⑤ 07 §10 の文言チェックを1項目ずつ自分で見る
```

検査は必ず全部通してから「直した」と言うこと（AGENTS.md クリティカルルール）。

```bash
npm test && npm run lint && npm run typecheck && npm run lint:content && npm run format:check
```

`npm run measure:readability` で文長と漢字密度のレポートも出せる。

## 4. 見え方を確かめる

文言は画面で見ないと分からない。**図鑑ならログイン不要で16人ぶん一度に読める。**

```bash
npm run dev
```

- `/nekumax` — 16人の一覧。呼び名・ひとこと・チーム役割・4行を全部確認できる
- `/welcome` — 診断本体。20問と結果画面（結果まで進むにはログインが要る）

ふりがなが出ているか、語彙メモの下線が出ているか、1文に下線が2本ないかを目で見る。

## 5. 判断に迷ったら

- **むずかしい語を残すか、やさしくするか** → 職場で実際に使う語なら残して語彙メモで支える。そうでないならやさしくする
- **説明を足すか、削るか** → 削る。1文に未知語が2語入るくらいなら情報を1つ捨てる
- **どの言い方が読めるか分からない** → その語を辞書で引いたときに何に着地するかを考える。**辞書が誤誘導する語が最悪**（「きりこみ役」は「切れ目・切り口」に着地して意味が壊れた）

迷ったら推測せず、07の該当節を引用して確認を求めること。
