# ルールの経緯

AGENTS.md の決まりが今の形になった経緯をまとめる。AGENTS.md には「いま守ること」だけを書き、
昔の事故の話や、取り消した決まりはここに移した（2026-10-11。AGENTS.md が長くなり、何を守ればよいかが読み取りにくくなっていたため）。

## 2026-10-11 の見直し

tomy さんから「Claude が作った言葉が多くて、私の理解とずれている」「Opus 5 のころに作られた謎の決まりを見つめ直したい」と指摘を受けた。
Claude が使ってきた言葉と AGENTS.md の決まりを、tomy さんの発言（7月24日〜10月11日の754件）と照らし合わせて調べ、
tomy さんに一覧を見てもらって、次のように直した。言葉の言い換えは `docs/用語集.md`。

- **報告の型（✅結果／📁範囲／🧪証拠／⏭次の一手／❓判断）をやめた。** 2026-08-05 に AI が自分で決めた型で、tomy さんが選んだものではなかった。
  何の結果・範囲・証拠かが見出しだけでは分からず、「次の一手」と「判断」はどちらも tomy さんへのお願いで重なっていた。
  2026-08-18 に「読めない」と言われてからも型は変えていなかった。新しい書き方は `docs/用語集.md` の「報告の書き方」。
- **「毎回の返事の最初に現在地を1行書く（例: 台帳#12・5歩中3歩目）」をやめた。** tomy さんの頼みは「どこまで進んだか分かる方法がほしい」だった。
  番号と歩数の形は AI の発明で、ほとんど使われていなかった。時間のかかる作業で「いま〇〇をしています」と一言伝える形にした。
- **「『閉じて』と言われたら」の決まりをやめた。** tomy さんは「閉じて」を一度も使っていなかった（言っていたのは「終わらせ方がよく分からない」）。
- **「作業の範囲を伝えて OK をもらってから始める」を、「始める前に一言伝えて、OK は待たずに進める」に変えた。**
  「OK をもらってから」は AI が足した部分で、2026-07-28「私の確認が必要になるまでは必ず進める」、2026-08-10「質問はせず自己判断で」とぶつかっていた。
- **「AI もアプリを立てて画面を撮って確かめる」を、「tomy さんの Mac では立てない」に変えた。**
  2026-08-11「ローカルでの検証はもうしたくない」、2026-08-19「終わったら閉じて。PC が重い」と食い違い、同じファイルの中でも矛盾していた。
- **ルール3（選択式）を書き直した。** もとは「選択式は読解確認だけ」だったが、tomy さん自身が4択・語群の穴うめ・複数選択を何度も頼んでいて、
  実際の教材にもあった。「話す・書く練習の代わりに選択式で済ませない」にした。
- **ルール4（Gemini の呼び方）を今の作りに合わせた。** もとは「Gemini はサーバー経由」だったが、2026-08-17 から学生のブラウザで一時的な接続キーを作る作りに変わっていた。
- **デプロイの注意点5（Worker の大きさ）に、有料プランのことを足した。** 2026-09-04 に Cloudflare は5ドルの有料プランに入ったと tomy さんから伝えられていたのに、無料プランの前提のままだった。
- **「技術的なことは聞かずに AI が決める」を足した。** 2026-08-05「全部やるべきなら確認はあまり意味はない」、2026-08-10「質問はせず自己判断で」。
- **言葉を直した。** 願いの台帳→要望の一覧、制約台帳→注意事項、門番・届け先→STG・本番、検問→止める仕組み、絶対規律→必ず守るルール（番号はそのまま）など。
  学生向けの「単語の間にスペースを入れる書き方」が、2026-08-07 ごろから開発の文章にまで広がっていたので、AGENTS.md ではやめた。
- 本番に出すタイミングは、tomy さんが「いまのやり方（授業前に自動・急ぐときは『本番まで』ですぐ出す）」を選んだ。

調べたときに分かったこと: AGENTS.md の決まりの大半は 7〜9月に Fable 5 と Opus 5 が書いた。2026-09-21 ごろからの Opus 5.5 は AGENTS.md を変えず、
`docs/constraints.md`（注意事項）を増やしていた。注意事項は330行・約20万字あり、整理はこのあと別に行う。

## ルール1（結果をぼかさない）

- 最初の版（2026-07-21）は「不正解・間違いです・ダメ を禁止。励まし＋次の行動」だった。tomy さんの好みと逆で、約6週間そのままだった。
- 2026-09-03 に禁止語から外したもの: 「不正解」「間違いです」「間違いだ」（判定の言葉。禁じると、判定そのものをぼかす方へ逃げる）と、
  「〜できなくても だいじょうぶ」「〜でなくて OK」など7語（2026-08-27 に AI が「ユーザーの指定」として記録していたが、
  tomy さんは「もともとそんな指示してない」と言った）。

## ルール9（国名）

- 2026-07-27 に AI が「新しい国名を画面や画像に出すときは、事前にユーザーへ確認する」を足した。これは指示の読み違いで、
  まなびマップの見せかたの話を、教材の本文のチェックにまで広げていた。そのせいで、会社の海外拠点すら説明できなくなっていた。
- 2026-08-23 に tomy さんが「タイが敵対関係にあるから出さないというだけ。国の名前の箇所は非表示でいいという指示を曲解されて今に至ります。
  mapで非表示にしてほしいだけ。タイ禁止以外のルールは無くしてほしい」と言い、取り消した。

## デプロイの注意点4（STG に上げてよいもの）

- 2026-08-05 の最初の版は「STG は main の中身だけ」だった。tomy さんは 2026-08-11 に「stgなのになんでmain？」と疑問を出し、
  2026-08-27「mainと同じブランチで動くSTGには価値がない」を受けて、比べる相手を `integration` に移した。
  チェックの仕組み（ブランチ名ではなく中身で比べる）は変えていない。これを、ほかのチェックを外してよい前例として扱わない。

## DB の変更の SQL（2026-08-26 の事故）

- コードは本番に載ったのに、DB に変更が入っていなかった。テストも CI も通ったまま、2日間だれも気づかず、7人が名簿から消えていた。
  それ以来、変更の SQL は `integration` に入れて自動で実行し、DB に頼る直しは DB に入っているかを確かめてから「直った」と言う。

## URL（2026-08-06）

  404 も保存されるのが理由だった。
