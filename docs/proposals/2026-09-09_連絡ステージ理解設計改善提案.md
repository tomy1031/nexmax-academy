## 1. 全体診断（3行）

1. **覚える「型」が1ステージに5種類ある。** 連絡の型が、まんが／リスニングでは「いつ・何が・どう なるか・何を して ほしいか」の4点、ページでは「事実だけ／数字／結論から／【 】／スタンプ」、ビルダーでは「だれに→1行目→くわしく→おねがい」、Slackの練習では「メンション→件名と事実→URL」、連絡文の練習では「【問題】【原因】【直る予定】」。**どれを覚えればよいかが決まらない。**
2. **産出（自分で書く・自分の声で言う）が順路に1本も無い。** `link` と `skit` は `gates: false` なので、実質の終点は4択の `renraku_quiz`。報告ステージには `meeting` が3本あるのに、連絡には0本。
3. **ことばを引く手が、最初の教材から無い。** ポップアップ辞書（`DictionaryText`）が配線されているのは `article` / `quiz` / `meeting` / `talk-game` だけ。連絡の1本目は**まんが**なので、学習者は最初から辞書なしで読み始める。

### 2.2 産出が順路に無い

- `src/lib/content-kinds.ts` L60 `link: { icon: "🔗", label: "リンク", href: …, gates: false }` ／ L67 `skit: { …, gates: false }`

実践3本（builder / slack / contact）は**1本もやらずに次のステージへ行ける。**

このステージ唯一の自由記述は `public/tools/hourensou/renraku_contact.html` L797 の
`<textarea class="slack-input" … placeholder="ここにSlackメッセージを書いてください...">`（上級タブに5つ）。
ただし**採点も、お手本も、記録も無い**——出口は L769 の `📄 PDF出力`（`window.print()`）だけ。

さらに、初級タブの**穴埋め欄そのものが採点されていない**。
`class="blank-input"` の欄（20か所以上）は `data-answer` を持つが、採点する関数

`renraku_contact.html` にそのクラスは1つも無く、採点ボタンも置かれていない。
ソカーの弁:「答えを入れても、○か×か、画面は何も教えてくれません」——**絶対規律1「結果をぼかさない」の手前で、結果が出ない。**

### 2.3 ことばを引く手が無い

- `DictionaryText` の配線先は `article-view.tsx` / `quiz-runner.tsx` / `meeting-session.tsx` / `talk-game-session.tsx` / `call-shell.tsx` の5つ。
  `src/components/manga/` `src/components/skit/` `src/components/listening/` には**1か所も無い**。
- 2026-08-27 の指定「全てのコンテンツについて、辞書を細かくつけるようにしてください」（`docs/constraints.md`）が**半分しか届いていない**。
- 語が辞書にあっても引けない例: `content/vocab/vocabulary.json` は 870語あり `後回し`（"Doing it after other tasks"）も入っている。

## 3. 提案（8件）

> 重さ **S** = データ（`content/*.json`・`*.data.js`）だけ ／ **M** = 共有部品か生成物を伴う ／ **L** = 新エンジン。
> 出典: (f)=fable (S)=ソカー (R)=rubric-checker。■=エンジン（`src/`）、●=データ。

### 提案1 ●S 「4点の型」をステージの背骨にする

正典を **「いつ・何が・どう なるか・何を して ほしいか」**（まんが p3 のヘンディのセリフ）に固定する。
ページの §1-2、スキットの `note`、もんだいの `explain`、ビルダーの intro 文言を、**同じ4語**に寄せる。
お手本の連絡文も1本に統一する（まんが p3 ＋ リスニング「明日の 18時から 19時まで…」）。
数は宣言しない（2026-08-17「数を 宣言しない」）ので、見出しは「連絡の パーツ」と呼び、**数は絵4枚で見せる**。
※ リスニング原稿の既存文「ポイントは 4つです」は**音声込みなので触らない**。 (f)(S)

### 提案2 ■M ポップアップ辞書を まんが・スキット・リスニング にも効かせる

`DictionaryText` を3つの本文に配線し、あわせて
（a）まんがの「あとまわしに」を **`後回し`** に戻す（規律2）、
（b）`合図`・`以降` を `content/vocab/vocabulary.json` に足す。
**この項目だけ `src/components/` に触れる**（検問が無い＝文章ルールだけが頼り）ので、着手前に画面の言葉で範囲を宣言する。 (S)

### 提案3 ●S リスニングを ページより前に置く

`docs/constraints.md`（2026-09-01）「**リスニングは 資料より 先に 置く**。並びは 聞く → 資料で 確かめる → 軽い 内容確認の もんだい」。
いまは article(2) → listening(4) で逆。
入れ替えると、まんが p3 の `note`「この 連絡は、**つぎの リスニングで** ヘンディさんが 読み上げる 連絡に つながります。」が**本当に「つぎ」になる**（いまは2教材あと）。 (f)

### 提案4 ●S 産出①「連絡メモ」— 4点を自分の日本語で書く（新規 quizset）

`content/quizsets/renraku_memo.json` を、**朝礼メモ（`asakai_memo.json`）と同じ型**で作る。
`phase: "production"` ／ `free` × 4問（1｜いつ／2｜何が／3｜どう なるか／4｜何を して ほしいか）。
各問に `starter`（型文。「明日の ◯時から ◯時まで、」）と `hints`（**答えは書かない**）、
`explain` にお手本（**答えたあとにだけ出る**＝模範解答は隠す。R4-4）。
場面はまんがと**別の日**にして、写すだけでは書けないようにする。 (f)(R)

### 提案5 ●M 産出②「連絡ミーティング」— 4点を自分の声で言う（新規 meeting）

`content/meetings/renraku_meeting.json`（`mode: "ask"`）。ヘンディさんが**チームメンバー役**。
質問4本＝4点、`notes: [{ ref: "renraku_memo", label: "連絡メモ", reportOnly: true }]` で提案4の答えをひきだしに置く
（朝礼が `asakai_memo` でやっているのと同じ建てつけ）。
`closing` と `affection.reward` は「連絡が なかった 日」の後日談にして、まんがと輪をつなぐ。
**報告＝meeting あり／連絡＝無し の非対称**がここで解消する。
作り置き音声は無くても動く（Live が読む）。音声は願い #259 と同じ扱いで後追いにする。 (f)

### 提案6 ●S リンク3本 → 2本に絞り、ビルダーを関門にする

- `renraku_builder` を **`gates: true`** にする（`stageContentRefSchema.gates` は既にある）。
  builder は `nexmax:link-done` を送る**唯一の1本**（`grep -c link-done` → builder 1 / slack 0 / contact 0）なので、関門にしても詰まらない。
- `renraku_slack` を**順路から外す**。builder の data.js 冒頭に「**旧 Renraku Master の ネイティブ化**」と書いてあるとおり、
  **同じものの新旧2版が同じ順路に並んでいる**。ファイルは消さない（報告クエスト非表示 2026-09-09 と同じ扱い）。
- `renraku_contact` は**最後に任意の成果物（PDF）として残す**（`link-done` を送らないので関門にはしない）。 (f)(R)

### 提案7 ●S もんだいを「4点を打つ」確認に直す

いまの `renraku_quiz` は**ナレーションの記憶テスト**（`r_blank1`「ポイントは ___ です」／`r_q4`「お願いは 全部で いくつ」）。
この2問を落とし、`keyword` × 4（「この 連絡の『いつ』は？」＝原稿を見ずに4点を打つ）＋ `choose` × 2（「この 文は どの パーツ？」＝読解確認なので選択式でよい）に差し替える。
`keyword` は表記ゆれを `normalize.ts` が吸収し、⭕❌がはっきり出る（規律1）。 (f)

### 提案8 ●M 連絡文の練習に「答え合わせ」を付ける（**判断が要る** — §5）

`blank-input` に採点が無い件（§2.2）。初級タブは加えて、答えが最初から
`<span class="answer-hint">`（黄色ハイライト・`renraku_contact.html` L142-149）で**見えている**ので、
「長いチャットから必要な情報を探す」という問いが成立していない。 (S)(R)

## 4. 推奨する新しい順路（`content/stages/renraku.json` の contents 差分）

```
   1  manga     renraku_manga                （そのまま）
-  2  article   renraku_lecture
-  3  skit      renraku_skit
-  4  listening renraku_listening
+  2  listening renraku_listening            ↑ 提案3
+  3  article   renraku_lecture              ↓ 提案1（4パーツ構成に）
+  4  quizset   renraku_quiz                 ↑ 提案7（4点を打つ）
+  5  skit      renraku_skit                 ↓ 提案1（note を 4点に）
-  6  link      renraku_builder
+  6  link      renraku_builder  gates:true  提案6
+  7  quizset   renraku_memo     【新】       提案4（書く）
+  8  meeting   renraku_meeting  【新】       提案5（話す）
-  7  link      renraku_slack                外す（ファイルは残す）
-  8  link      renraku_contact
+  9  link      renraku_contact              任意・成果物（PDF）
```

階段: **聞く(2) → 読んで確かめる(3) → 4点を打つ(4) → まねて言う(5) → 選んで組む(6) → 自分で書く(7) → 自分の声で言う(8) → 紙に残す(9)**
関門: 1・2・3・4・6・7・8 → 「ステージ クリア」が出るのは **meeting のあと**になる（いまは4択のあと）。

## 6. やらない方がいいこと

| 案 | やらない理由 |
| --- | --- |
| リンク3本の HTML を article/quizset に作り替える／ビルダーを React 化する | 2026-08-29「中身の HTML は そのまま 写す」＋ 2026-07-29「完成している既存UIの作り直しをしない」 |

## 7. 別タスクに回すもの（このステージの外）

### 7.1 ルーブリック R5-1 が、いまの指定と逆を向いている

`docs/design/review_rubric.md` R5-1「誤答時のフィードバック文言をすべて引用せよ ／ 全てが励まし＋リソース誘導。**正解の即開示は違反**」。
これは 2026-08-27「正解が何かをわかるようにそこだけフォーカス」と
2026-09-03「正解か不正解か…明記しないと理解できない箇所で綺麗事のようなメッセージが表示されるのは害でしかない」と**逆**。
このまま検収を回すと、**ユーザーが直させた形が毎回「違反」として上がってくる**（実際、今回の rubric-checker も
`renraku_slack.html` の「不正解。設計書ではなく仕様書です。」を R5 の疑いとして回してきた）。
`docs/design/` は検問対象なので、**専用タスクとして起票する**。

### 7.2 報告しないことにしたもの（誤検知）

- rubric-checker の R6-5「`renraku_lecture.json` の `"caption": "ケーススタディ"` が学習者の画面に出ている」は**画面には出ない**。
  `src/components/article/article-view.tsx` L705 で `caption` は `alt` にだけ渡している
  （2026-08-25「画像の下の文字は不要」の実装）。読み上げにだけ届く語なので、直すとしても優先度は低い。
