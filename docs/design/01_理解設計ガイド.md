## 1. 学習者モデルと「二重の目的」

### 1.1 学習者はこういう人である

- カンボジアのIT専攻学生。**ITは得意分野であり、誇りである。**
- 日本語学習歴は約1年。N5〜N3挑戦レベルまで**教室内に幅がある**。
- 「間違えたら恥ずかしい」という不安を強く持ちやすい。発話の失敗は自尊心に直結する。
- スマートフォン中心の生活。ゲーム・SNS・漫画のUI文法は母語のように読める。
- 日本語そのものより、「日本で働く自分」の解像度が上がる瞬間にモチベーションが動く。

### 1.2 目的は二重構造になっている

| 層 | 目的 | 教材上の現れ方 |
|---|---|---|
| 表の目的 | 日本のITの状況・働き方・開発実務を学ぶ | 報連相、要件定義、開発工程、ヒアリング、技術選定 |
| 裏の目的 | N3までの日本語学習のモチベーションを作る | すべての実務体験が「日本語で聞く・話す・書く」を通してしか進まない構造 |

**最重要の設計判断**: この教材は「日本語を学ぶ」と「ITの仕事を学ぶ」を**分けない**。日本語は科目ではなく、仕事を進めるための道具として毎回登場する。だから学習者は「日本語の勉強をしている」感覚が薄いまま、報告文を書き、顧客に質問し、議事録を埋めている。単語ゲームのステージ1の例文自体がこう語りかける——「今までの勉強は『N5、N4に合格するため』のものでした」「仕事の現場では、もっと実践的な日本語が必要です」「この1年の頑張りが、皆さんの未来を決めます」。**語彙ゲームの例文にまでキャリアの物語を載せる**。これが裏の目的の実装である。

### 1.3 AIへの指示のしかた

> 教材のゴールを「文法・語彙の習得」と書かない。「この教材のあと、学習者が日本のIT職場で何をできるようになるか」を1文で書く（例:「検証環境の停止を、いつ・何が・どうなる・何をしてほしいかの順で連絡できる」）。日本語は常にその行動の手段として登場させる。

## 2. アプリ全体の構造 — 1つの会社、1つの物語、5つの層

### 2.1 ナラティブの縦糸

全教材は「**株式会社ネクストメイクに入社した新入社員の研修**」という1本のロールプレイで貫かれている。

- `about.html` が入口:「みなさんは、今日からIT企業『ネクストメイク』の新入社員です」「わからないことは、恥ずかしがらずに聞いてください。失敗も勉強です」——**最初に役割を与え、同時に心理的安全を宣言する**。
- 固定キャラクターが教材を横断して再登場する:
  - **ヘンディ先輩**（インドネシア出身。プログラマーからPMに昇格した外国人社員）——講師・先輩・ロールモデル。「外国人としてすでに日本のIT企業で成功している人」を案内役に置くことで、学習者は自分の未来像として彼を見る。
  - **藤木さん**（取締役）——報告・相談の相手役。上司との距離感の教科書。
  - **神社長（かみしゃちょう）**——「お客様は神様です」を体現する天使の輪の付いた顧客キャラ。「AIでいいカンジによろしく！」と無茶を言う。**日本のIT受託の理不尽を、恨みではなく笑いに変換する装置**。
  - **山本社長（Aoba株式会社）**——抹茶カフェのプノンペン出店という、学習者の生活圏に接続した顧客。
- 同じ世界の中で、報告の相手も、ヒアリングの顧客も、ゲームの敵も繋がっている。**新しい教材を作るときは新しい世界を作らず、この世界に新しい場面を足す。**

### 2.2 スパイラル・カリキュラム（5つの層）

1つの単元（例:「連絡」）は、5つの層で最低3回以上、形を変えて繰り返される。

| 層 | 教材 | 学習者がすること |
|---|---|---|
| ① レクチャー | `lecture/renraku/` | 原理を読む（良い例/悪い例の対比） |
| ② リスニング | `listening/renraku/` | 実務会話を聞き、キーワードを拾い、穴埋め・議事録で確認する |
| ③ シミュレーション／ゲーム | `slack.html`, `train.html`, waterfall_quest | 実務の意思決定を体験する |
| ④ 単語ゲーム | `wordtest/`（DATA DIVE） | 同じ単元の語彙をアーケードで反復する |
| ⑤ まとめ | `summary/`（まなびの島） | 期末前に横断復習する |

**同じ語彙・同じ場面・同じキャラが層を替えて再登場する**から、1回の接触で覚えられなくても構わない。この冗長性が、N5とN3挑戦の混在クラスを両方成立させている。

### 2.3 1単元の型（章の進行テンプレート）

```
導入ストーリー（役割と状況の提示）
→ 重要語彙の先出し（6語前後、読み＋英語＋実務例文）
→ インプット（音声・スライド・漫画。受け身にさせない仕掛け付き）
→ 変換（穴埋め Drag→Type、キーワード発見、議事録完成）
→ 産出（ロールプレイ、自由記述、AI対話、Live音声）
→ 成果物（連絡文、要件定義書、ワイヤーフレーム…）
→ 模範解答との比較（最後まで隠しておく）
```

## 3. 理解設計の13原則

以下、各原則を「原則 → なぜ効くか → このアプリでの実装例 → AIへの指示 → アンチパターン」の形で示す。**実装例はすべて本リポジトリに実在するもの**であり、新教材の水準の物差しとして使う。

---

### P1. 学習者を「学生」ではなく「役割を持つ当事者」にする

**なぜ効くか**: 問題を「解かされる」人は受け身になる。役割（新入社員・ヒアリング担当・PM）を与えられた人は、場面の中で自分の行動を選ぶ。緊張と誇りが同時に生まれる。

**実装例**:
- お客さまインタビュー教材では、学習者の**Webカメラの実映像**がZoom風画面の自分タイルに映る。アバターではなく本人の顔。指示書に明記——「アバター画像は使わない」「学生の顔：Webカメラの実映像を表示する」。訪問前には「🔔 ドアを ノックする」ボタンを押して入室する。
- waterfall_quest はメンバー全員の名前を入力させ、**会話パートの主人公セリフをメンバー間でローテーション**させる（全員に主役の番が回る）。
- リスニング教材の冒頭:「あなたはヘンディさんのチームメンバーです。山本社長への質問とその答えに注目して聞いてみましょう」——聞く前に**視点**を配る。
- 第5話ゲストハウス編では、ヘンディ先輩が「口コミには英語のものもあるよ。あなたの語学力が役に立つね！😊」と言い、顧客は「昔、カンボジアにも行きましたよ。アンコールワット、最高でした」と話す。**学習者の出自そのものが、物語の中で「戦力」として扱われる。**
- 要件定義ワークでは、カンボジア人学習者だけが持つ知識（クメール語投稿はいいね4倍・コメント10倍のデータ、プノンペンの若者はスマホしか使わない）が、日本人の社長を動かす提案材料になる。**教える側と教わる側が逆転する瞬間**を意図的に作っている。

**AIへの指示**:
> 教材の最初の画面で「あなたは誰で、なぜ今この行動をするのか」を必ず与えること。学習者の母国・語学力・現地感覚が「武器」になる場面を、シナリオに最低1箇所埋め込むこと。

**アンチパターン**: 「次の会話を聞いて問いに答えなさい」で始まる教材。学習者が第三者・採点対象になっている。

---

### P2. 興味は「解ける謎」と「開く箱」で設計する

**なぜ効くか**: 人は情報を与えられるより、**隠されたものを自力で開ける**方が夢中になる。開ける手段が学習行為そのものになっていれば、学習＝報酬になる。

**実装例**:
- **要件ボードの「？？？」**: インタビュー画面の右側に10枚のカードが「？？？」で伏せられている。良い質問をした瞬間、カードが `rotateX` でフリップして緑に開き、トースト「⭕ 「予算」が わかった！」が出る。全部開くと「🎉 ぶんぶの要件がわかりました！お礼を言って、インタビューをおわりましょう」。
- **隠し原稿リベール**: リスニング（相談・要件定義）では原稿全文が灰色の伏せ字で表示され、聞き取った語を入力すると**該当文字が緑のアニメーションで浮かび上がる**。クリア条件は「原稿表示率30%」。学習者は原稿を「読まされる」のではなく「発掘する」。
- **消去法の可視化**: しつもんゲームLv0は「私はなんでしょう？」クイズ。質問するたびに候補動物カードに✕が付いて絞られていく。指示書はこれを「消去の可視化（最重要演出）」と呼び、「誤消去は学習を壊すため」曖昧な質問では消去しない側に倒す判定ルールまで定めている。
- **正解が鍵になる段階開放**: 全問正解で初めてリスニング原稿が開示される。スコア30点で次ページが開く。あいづち教材では**開錠パスワード自体が「なるほど」「そうなんですね」という学習対象のあいづち**になっている——復習が開錠になる。
- **模範解答は最後まで隠す**: パスワードゲート（先生が授業で口頭伝達）の先にだけ、模範要件定義書と完成サイトがある。

**AIへの指示**:
> 情報開示は必ず「学習行為を鍵にした段階開放」にすること。原稿・答え・模範解答・次のステージは、聞き取り・正解・質問の成功によってのみ開く。演出（フリップ、文字の浮上、✕の付与、紙吹雪）で「開いた瞬間」を必ず祝うこと。

**アンチパターン**: すべての情報が最初からスクロールで読める教材。もしくは、学習と無関係なタイマーやスタンプだけのゲーミフィケーション。

---

### P3. 案件のリアリティは「ディテールの網」で作る

**なぜ効くか**: 学習者は「作り物の問題」を敏感に見抜く。逆に、実在しそうな固有名詞・数字・古臭さ・不便さが揃った瞬間、案件は「本物」になり、真剣さが変わる。

**実装例**:
- **数字の実在レンジ**: 予算30/50/20/40万円・月1万円サブスク、クーポンサイト手数料が月5万円、DM返信に毎日1時間、生徒120人・先生4人・1クラス15人、抹茶ラテ$3.5（学生$2.5）、制作費80万円以内・月額5,000円以下・納期3ヶ月。**その規模の事業者なら本当にありそうな数字**だけを使う。
- **納期は「事業イベント駆動」**: 「3ヶ月後のリニューアルオープンまで」「春キャンペーンまで」「新学期まで」「観光シーズンまで」「孫が大学に行く前まで」。締切に人間の事情がある。
- **日本の中小企業ITの現実を再現したモック**: ヘアサロンの古い自社サイトには、アクセスカウンター「あなたは034872人目のお客さまです」、「このページは Internet Explorer で見ることをおすすめします」、2年前で止まったお知らせ、「ご予約はお電話にて」。この**古さ・不便さ自体が要件の伏線**である。
- **実在技術名を使う**: Firebase / React / Laravel Breeze / Socialite / WordPress / WooCommerce / Shopify / Docker / git pull / エラー500。技術選定リスニングでは「FirebaseはReactと一緒に使うのが簡単」vs「今回はバックエンドがLaravelだからBreezeがいい」という**本物の技術判断の対立**を聞き取らせる。
- **制約の網で「正解の必然性」を作る**: 技術選定ワークでは、①ブログを月2〜3回書きたい ②更新するのはプログラミングできない現地スタッフ ③半年後にEC追加 ④月額5,000円以下 ⑤担当エンジニア奥田さんはWordPress経験あり・Shopify未経験、という**5つの独立した制約が全部WordPressを指す**ように設計されている。学習者は「正解を教わる」のではなく「制約を積み上げたら答えが1つに絞れた」体験をする。仕様書の言葉では「WordPress一択の必然性を積み上げる」。
- **エンジニアのスキルも制約になる**: 奥田さん（入社3年目、レガシーASP.NET保守から始めてWordPress中心へ）というキャラの職歴が、そのまま技術選定のリスク評価材料になる。「知らない技術を選ぶ＝学習時間＝コスト・リスク」。

**AIへの指示**:
> 案件を作るときは必ず①業種と規模に整合する具体的な数字（価格・人数・頻度・予算）②事業イベント駆動の納期 ③現状の不便さを体現するモック（古いサイト・DM運用・紙・電話）④実在する技術名 ⑤複数の制約が1つの結論を指す「制約の網」——の5点セットを設計すること。数字はダミー（100万円、10人）ではなく、その業種で現実的なレンジから選ぶこと。

**アンチパターン**: 「ある会社がアプリを作りたいと言っています」という無名・無数字の案件。制約がないので、どんな答えでも正解になり、考える必然性が消える。

### P4. 情報を一箇所に置かない — 分散ヒント設計

**なぜ効くか**: 実務では、要件は1つの文書に書かれていない。雑誌記事・Webサイト・SNS・会話に散らばった断片を集めて仮説を立てる。この「調査→仮説→質問」のループ自体が、要件定義の本体である。

**実装例**:
- 要件定義ワーク v2.2 では、ヒントが**3種類の架空メディア**に分散している: ①Webマガジン「NEXT ASIA BUSINESS」の社長インタビュー記事（「茶道体験は事前予約制」→予約フォームの伏線）②Aobaの日本語サイト（予約が電話のみ・言語切替なし・円表示→「ないもの」に気づかせる）③Instagramのテスト投稿データ（クメール語版はいいね4倍・コメント10倍→データ提案の弾）。
- お客さまインタビューでは、Facebookのコメント欄の何気ない一言「お孫さんが LINE、やってくれてるんですね😊」が、後のインタビューで「孫が来年、遠くの大学に行ってしまう」という納期の理由に繋がる。**調査と会話が繋がったときの「気づき」の快感**を設計している。
- **秘匿情報の分離ルール**: 設計書のチェックリストに「秘匿情報（予算の金額等）は模擬ページに書かない」。調べれば分かる情報と、聞かないと分からない情報を厳密に分ける。だから調査にも質問にも、それぞれ固有の価値が生まれる。
- 事前調査には3問のクイズがあり、**答えは必ず模擬ページの中にある**（読解確認）。全問正解しないと質問メモ画面に進めない。

**AIへの指示**:
> ヒアリング・要件定義系の教材では、情報を「①模擬メディアに書いてある（調査で得る）②相手の頭の中にだけある（質問で得る）」の2層に分けて設計すること。②を模擬ページに書いてはいけない。①には後の会話で回収される伏線を最低1本埋めること。調査クイズの答えは必ずページ内から引けるものだけにすること。

**アンチパターン**: 顧客プロフィール1枚にすべての要件が書いてあり、学習者は読んで写すだけ。あるいは、調査ページに予算まで書いてあり、質問する理由がなくなる。

---

### P5. 相手役は「意図的に曖昧」にする — キャラの癖こそカリキュラム

**なぜ効くか**: 現実の顧客は要件を整理して話さない。曖昧さ・脱線・要望過多こそが実務の本体であり、それに対処する技法（深掘り・軌道修正・優先順位付け・持ち帰り）は、**曖昧な相手がいないと練習できない**。

**実装例**:
- 全ヒアリングシナリオ共通の契約: 顧客は冒頭に固定の2〜3文で「作りたいアプリ＋一番の痛み」だけを話し、以降は**聞かれるまで何も言わない**。ペルソナには「【あなたが知っていること】＝隠れ要件と1対1対応。聞かれたら答える。聞かれるまで言わない」と明記。
- **キャラの「癖」が1話1技法の練習問題になっている**:
  | 話 | 癖 | 練習される技法 |
  |---|---|---|
  | ベーカリー | 会話が犬の話に脱線する | 「ところで、アプリの話ですが…」で優しく戻す |
  | ヘアサロン | 専門用語を使うと「それはどういう意味ですか？」と聞き返す | 顧客の言葉で話す（平易化） |
  | 農園 | 支払い方法を聞くと「おすすめはありますか？」と逆質問する | 「会社で調べて、またご連絡します」＝持ち帰り |
  | 塾 | ほしい機能を1回に2つ続けて言う。優先順位は聞かれたときだけ即答する | 要望過多への優先順位付け |
  | ゲストハウス | 英語が混ざる。カンボジアの思い出で脱線する | 外国語対応・アイスブレイク |
- ペルソナは10か条の「話し方のルール」で統制され、**第5条だけが話ごとの「癖」の差し替えスロット**になっている。拡張時はこの1条を入れ替えるだけで新しい技法の練習問題が作れる。
- 山本社長のプロンプトには「意図的に曖昧にする設定（深掘りで判明）」が明記されている: クメール語対応→初期は「まだ決めていないんです……どう思いますか？」、深掘りされたら「現地スタッフに任せたいと思っています」。**曖昧さは2段階で設計**し、深掘り質問にだけ2段目を開く。
- 会話の中に**30分制約**を入れる:「30分しか時間が取れずすみません」。実務の時間圧力を演出しつつ、ダラダラ聞き続けられない緊張を作る。

**AIへの指示**:
> 相手役ペルソナには必ず①聞かれるまで言わない情報リスト（隠れ要件と1対1対応）②2段階の曖昧さ（初期回答／深掘り回答）③教育目的を持つ「癖」を1つ——を設計すること。癖は「この教材で練習させたい対処技法」から逆算して選ぶこと。

**アンチパターン**: 聞けば何でも整理して答えてくれる「良い顧客」。学習者は質問リストを上から読むだけの作業になる。もう1つの失敗は、癖を複数盛り込んで会話が破綻すること——**癖は1キャラ1つ**。

### P6. インプット→変換→産出の階段を必ずかける（アウトプット主体の正体）

**なぜ効くか**: 資格勉強型のインプット偏重は「わかったつもり」で終わる。逆にいきなり自由発話をさせると、N5の学習者は沈黙する。この教材の強さは、**同じ内容を認知負荷の違う形式で3〜5段階に分けて、最後は必ず産出で終わる**ことにある。

**実装例（階段の実物）**:
- **聞く**: 速度変更（0.5〜1.5x）付きプレイヤー。「聞こえた日本語を、どんどんメモしてください」というメモ導入。
- **拾う**: キーワード発見型スコアリング（漢字+5点・ひらがな+3点・その他+2点、関係ない語3回で-1点）。聞こえた断片の入力自体が得点になる。
- **埋める**: 穴埋めは **Drag（語群から選ぶ）とType（打つ）のトグル切替**。同じ問題が選択式にも記述式にもなる——これがレベル差対応の中核部品。判定は `data-answer="報告,ほうこく"` のように**漢字・ひらがな・カタカナ・ローマ字・全半角の表記ゆれを全て許容**。
- **構造化する**: 「議事録を完成させよう」——会議名／主なテーマ／決まったこと／次回までにすること、という実務文書の型に聞いた内容を流し込む。
- **書く**: 連絡文ワークは2レベル。初級は同僚の砕けたチャット（「さっきからログインできないってユーザーから連絡が来てるんだ…」）を【問題】【原因】【直る予定】のテンプレメールに転記する変換課題。上級はSlack風UIで自由記述、最終問は状況設定から自分で考える完全自由作文。
- **話す**: スキット暗唱（「10分で記憶」→「見ないで言えるようになりましょう！」）→ ペアロールプレイ → **Gemini Liveでの完全自由発話**（インタビュー教材）。
- **設計書の宣言**: お客さまインタビューの設計書は、選択式の質問ボタンを検討した上で**不採用**と明記している——「本プロジェクトの核は『リアルなやりとり』。選択式に逃げない」。選択式は事前調査（読解確認）だけに限定されている。

**AIへの指示**:
> 1教材の中に必ず「聞く/読む → 拾う/埋める（表記ゆれ許容） → 構造化する（実務文書の型） → 産出する（書く・話す）」の階段を作ること。産出フェーズで選択式を使ってはいけない。選択式が許されるのは読解確認だけ。自由入力の前には必ず足場（例文ボタン・テンプレチップ・型文・2段階ヒント）を置くこと。

**アンチパターン**: ①講義→4択→次の講義、の無限ループ（産出がない）。②足場なしの「自由に書いてみましょう」（白紙恐怖で止まる）。③正誤判定が厳格すぎて、ひらがなで書いたら不正解になる。

### P7. 感情を設計する — 共感がエンジン

**なぜ効くか**: 「要件定義を学びましょう」では動かない学習者も、「買えなかったお客さまの悲しい顔を見たくない」店長は助けたくなる。**動機の物語化**は、知識を記憶に変える最短経路でもある。

**実装例**:
- ベーカリー編の起点は、Instagramの客コメント「15時に行ったら、もう何もありませんでした😢 ざんねん…」と、店長の「買えなかったお客さまに、申し訳なくて」。**業務効率化ではなく利他が動機**に置かれている。
- 農園編:「形の悪い野菜が、たくさんあるんです。おいしいのに、捨てるのはもったいなくて」——フードロスの情動。納期の理由は「LINEを手伝ってくれている孫が、来年の春、遠くの大学に行ってしまう」。
- 塾長の口癖「一人ひとりを、大切に。」は、会話にも時々混ざるとペルソナに指定され、「成績はアプリで見せない（面談で直接話したいから）」という**教育理念に基づくスコープ外**の理由になっている。機能の取捨選択に人格が宿る。
- **AIの返答に感情フィールドがある**: 山本社長のレスポンスは `feeling`（嬉しい/驚いた/悩んでいる/期待している/困っている）を持ち、アバター横に絵文字バッジで表示される。学習者がデータを添えて提案すると社長は「そんなに違うんですか！正直、クメール語は後回しにしようと思っていたけど、考え直したほうがいいかもしれないですね」と**驚いて動く**。良い仕事が相手の感情を動かす体験を、システムが返す。
- 「まなびの島」の共感ゲームは、**感情の読み取り自体を問題形式化**している: ①「あいての きもちは？」（5分類から選ぶ）→②「どう こたえる？」の2段階問題。言葉が合っていても感情の読みがズレていれば満点にしない（ただし極性が近ければ0点にもしない）。

**AIへの指示**:
> 案件・場面には必ず「顧客・相手の人間的な動機（利他・もったいない・理念・家族）」を1つ設計し、それを冒頭の固定セリフか調査素材の中に見えるように置くこと。AI相手役には感情フィールドを持たせ、学習者の良い行動（データ提案・共感・確認）に対して感情が動く反応ルールを書くこと。

**アンチパターン**: 動機が「売上を上げたい」だけの顧客。感情のないQ&Aマシンとしての相手役。

### P8. フィードバックは「正誤」ではなく「次の行動」

**なぜ効くか**: コミュニケーション練習で「不正解」を突きつけると、学習者は発話しなくなる。この教材群は**「不正解」「間違い」という語彙を全教材で使わない**という規律を敷いた上で、失敗を「次に何をすればいいか」に必ず変換する。

**実装例（実際の文言）**:
- クイズ誤答:「🔍 おしい！ もう一度、上のページを見てみましょう。」（正解を教えず、読み直しに戻す）
- あいづち上級の3段階評価:「とても自然／使えます／この場面では少し注意」——指示書に「合いにくい場合でも、学生が傷つかない表現にする」。
- 0点でも:「🌱 よくがんばりました！」。ほめ要素が1つもないときの救済文言まで用意——「（顧客名）さんと N回 やりとりできました。」**手ぶらで帰さない**。
- 未達成要件は「❌」ではなく「🔭 つぎは これを 聞いてみよう」として、**答え＋聞き方ヒント（『ご予算はどのくらいですか？』と聞いてみよう）をセットで開示**→そのまま次周回の台本になる。
- 終了ボタンすら教育機会:「おわる前に、お礼は言いましたか？『ありがとうございました。会社で整理して、またご連絡します。』」
- API障害時も:「🤖 AIがこんでいます。いまは かんたん判定でつづけます。」——**システムエラーさえ不安を与えない言い換え**。
- フィードバックの型（スキル文書より）:「まず肯定する。何が良かったかを短く言う。もっと自然な表現を1つ示す。次に使える場面を示す。」しつもんゲーム指示書では「よかったところ→つぎはこうするともっといい」の順序を全テキスト共通ルールとして課している。
- **判定は学習者有利に倒す**: AI判定とローカルキーワード判定の**和集合**を取る（取りこぼし救済）。表記ゆれ全許容。曖昧な質問では消去法の✕を付けない。「ゆるく判定してよい」とプロンプトに明記。
- ヒントは**答えを言わない**: 2段階ヒントの2段目は「完成した答え」ではなく「今週、私は〇〇へ行きました。」のような**穴あきパターン文**。学習者が自分の内容を入れる余地を必ず残す。
- 詰み防止:「3ターン連続で進展がない場合、AIが自発的にヒントを話す（1ゲーム最大2回）」。ヒント使用は記録されるが**減点はしない**。

**AIへの指示**:
> フィードバック文言に「不正解」「間違い」「ダメ」を使わない。誤答には①励まし＋②リソースへの誘導（もう一度ページを見る／もう一度聞く）を返す。未達成項目は「次に試す行動＋そのための例文」に変換する。判定ロジックは偽陰性（正しいのに落とす）を偽陽性より重い罪として設計する。ヒントは方向→型文→例文の3段階で、完成解は最後まで出さない。

**アンチパターン**: ①赤い✕と「不正解です」②正解をすぐ表示して次の問題へ進む（学習者が自分で直す機会を奪う）③判定が厳密一致のみで、ひらがな回答や言い換えを弾く。

### P9. ゲームの仕組みそのものを教訓にする

**なぜ効くか**: ゲーム要素が「学習の後のご褒美」だと、学習とゲームが分離して両方薄まる。この教材のゲームは、**ルール自体が実務の法則のメタファー**になっているため、遊ぶこと＝法則を体感することになる。

**実装例**:
- **waterfall_quest の隠しリスク**: 上流工程でミス選択をすると `hiddenRisk` が蓄積し、テスト工程到達時に「たまっていた『バグ』が爆発するぞ...！」——risk×10の全体ダメージ＋risk×30万Gの予算損失。**「上流の雑さは下流で複利になって返ってくる」というウォーターフォールの本質が、ゲームメカニクスそのもの**になっている。riskゼロなら「すごい！バグはひとつもなかった！」。
- **毎ターン人件費で予算が減る**（人数×5万G/ターン）——時間＝金というPM感覚の暗黙学習。
- **連続ミスはダメージ倍率が上がる**——失敗の連鎖は傷を深くする。
- **敵を「倒す」のではなく「説得する」**:「『せっかちな神社長』を説得した！」。ITの仕事の敵は人ではなく、すれ違いである。
- **IT デュエルモンスターズの生贄召喚**: 「単体テスト」を場に出してリリース（生贄）しないと「結合テスト」が出せない。**下位工程の積み上げなしに上位工程は実行できない**というプロセスの依存関係が、カードゲームの召喚ルールで表現されている。カウンターカードは「Phase2の提案」「仕様凍結」「議事録の確認」「見積もりの根拠提示」——発動時に**実際に顧客に言うべき台詞**（論破の根拠）が表示される。勝利条件の1つは「デッキ切れ＝クライアントの要求が尽きた」。
- **ゲームオーバー→反省クイズ→復活**: コンティニュー時は、プレイ中にミスした問題だけが再出題され、全問理解すると「倒れていたメンバーが復活した！」。救済予算は出るが、クリア画面の「真の最終利益」からは差し引かれる——**失敗しても続けられるが、成績には正直に残る**。
- **DATA DIVE の中心体験の防衛**: 改修指示書に「画面奥から迫ってくるIT用語を、読みをひらがなで入力して止めること。この体験は必ず残す」「迫ってくる対象をバグや敵に変えないこと。迫ってくるのは、必ずIT用語そのものにする」。**ゲームの敵＝学習対象そのもの**という等式を、デザイン刷新でも壊させない。

**AIへの指示**:
> ゲーム教材を作るときは、先に「体感させたい実務の法則」を1文で書き、その法則をルール（リソース・ダメージ・召喚条件・勝利条件）に翻訳すること。法則と無関係な敵・スコア・タイマーを飾りとして足してはいけない。ゲームオーバーには必ず「理解による復活」の道を用意し、ただし救済は成績に正直に記録すること。

**アンチパターン**: 学習内容と無関係なミニゲーム（覚えたらシューティングで遊べる等）。敵がIT用語ではなく謎のモンスターになっている語彙ゲーム。

### P10. 日本語の足場は「消す」のではなく「重ねる」

**なぜ効くか**: 難語を消すと実務から遠ざかり、そのまま出すと学習者が溺れる。この教材は**難しいものを支援付きで出す**方針を、5層以上の足場の重ね掛けで実装している。

**実装例**:
- **全漢字ルビ**＋**ふりがなトグル**（既定ON、消すと背伸び練習になる）。CSSは `.ruby-off ruby rt { display:none; }` の1行。
- **n4-word 語彙ポップアップ**: 約280語の辞書（`'昇格': { reading:'しょうかく', meaning:'promotion' }`）。N4超の語だけ青字＋点線下線になり、ホバーで読み＋英語が浮く。**本文は読ませ、難語だけ支援する**。
- **分かち書き＋短文**:「1文15〜30字・文節間スペース」の規律。初級者向けページほど濃くかける。
- **音声は0.75倍速が既定**（ピッチ維持）、0.5/0.75/1.0を学習者が選ぶ。設定は教材横断でlocalStorage共有。
- **常時字幕**: Live会話は入出力両方の文字起こしをリアルタイム表示。聞き取れなくても読める。
- **🆘フレーズカード**:「すみません、もう一度おねがいします」「『◯◯』は、どういう意味ですか？」「少し考える時間をください」——**聞き返しは恥ではなくスキル**という思想を、ガイド・ペルソナ（困っていたら「ゆっくりでいいですよ」と言う）・UIの三方から支える。
- **語彙の先出し→即回収**: 各話の「きょうのことば」6語は、直後のインタビューで顧客が実際に使う語から選ばれている。
- **AI発話の統制**: 全ペルソナに「JLPT N4レベル」「1回の返事は1〜2文」「学生の日本語が間違っていても直さない。わからなければ聞き返す」を強制。文法訂正はコーチ役（advice）の仕事で、**相手役は絶対に直さない**。
- **二重テキスト管理**: 表示用テキストはルビHTML、AI・判定用は プレーンテキスト、と**同じ内容を2形式で持つ**スキーマ規律（`label/secret/hint` はルビ、`fact/persona/keywords` はプレーン）。
- **入力リテラシー自体を訓練**: テスト前の「ひらがな入力チェック」（『ようけんていぎ』を打たせてIME確認）、「日本語入力になっているか確認してください」警告、IME確定Enterの誤送信対策。**日本のIT職場で必要な日本語入力スキル**まで教材の守備範囲。

**AIへの指示**:
> 実務語彙を平易な語に置き換えてはいけない（「要件定義」を「決めること」にしない）。代わりに、ルビ・英語併記・語彙ポップアップ・例文・音声・字幕・フレーズカードを重ねること。表示用（ルビHTML）と判定/AI用（プレーン）のテキストは必ず分けて持つこと。AI相手役に学習者の日本語を訂正させてはいけない——訂正はコーチ枠で行う。

**アンチパターン**: ①「やさしい日本語」にしすぎて、職場で聞く語彙と乖離する ②ルビHTMLをそのままAIプロンプトや判定文字列に流し込む ③相手役AIが会話中に文法を添削し始めて、ロールプレイが崩壊する。

### P11. レベル差（N5〜N3挑戦）は「同じ教材の別モード」で吸収する

**なぜ効くか**: レベル別に教材を分けると、下のクラス扱いされた学習者の自尊心が傷つき、教師の運用も破綻する。この教材は**全員が同じ教材を使い、負荷の調整装置を学習者自身が握る**。

**実装例**:
- **Drag/Typeトグル**: 同じ穴埋めが、語群ドラッグ（認識）にも直接入力（想起）にもなる。
- **ふりがなトグル・速度選択・ヒント2段階**: 全部学習者側のスイッチ。
- **初級/上級タブ**: 連絡文ワーク（テンプレ転記→自由作文）、おうむ返し（初級20問→上級20問）、あいづち（枚挙フィードバックのみ→3段階評価）。
- **星の質的評価**: gow1h はクリアで★1、深掘り質問2件以上または高速クリアで★2、両方で★3。**合格ラインは低く、上限は高く**。N5の学習者は★1で達成感を、N3挑戦者は★3を狙って深掘りを磨く。
- **テストとゲームスコアの分離**: 指示書に「テストの合格判定とゲーム用スコアは分ける」。評価（80%合格）と遊び（コンボ・ランク）を混ぜない。
- **難易度の実装は速度と時間**: DATA DIVE の「かんたん」は速度0.5倍・時間2倍。**問題を減らすのではなく、時間圧を変える**。

**AIへの指示**:
> レベル別に教材を複製しない。1つの教材に、学習者が自分で操作できる負荷調整（Drag/Type、ふりがな、速度、ヒント、初級/上級タブ）を組み込むこと。達成は「合格ラインは低く、星の上限は高く」の2軸で設計すること。

**アンチパターン**: 「初級者用ページ」「上級者用ページ」の分離。低い方に割り当てられた学習者のモチベーションが下がり、教師のページ管理も倍になる。

### P12. AIは「相手役」と「コーチ」に分離する

**なぜ効くか**: AI対話教材の失敗の大半は、AIが「何でも知っている先生」として振る舞い、ロールプレイと指導が混線することにある。この教材はAIの役割を構造的に分けている。

**実装例**:
- **レスポンスの3分割**: `{ answer:"山本社長の回答", feeling:"感情", advice:{ message:"前向きな助言", better_question:"より自然な質問例", word_note:"語彙メモ" } }`。answer は世界の中の人物、advice は世界の外のコーチ。学習者のUIでも吹き出しとアドバイスカードが視覚的に分かれる。
- **スキーマの技術的強制**: プロンプトで「JSONで返せ」と頼むだけでなく、Gemini の `responseSchema`（構造化出力）で形式を強制。**プロンプト頼みにしない**。
- **嘘をつかせない多層制約**: ①「事前に与えられた情報にないことは作らないでください」②COMPANY_DATA に「未確定情報への返答方針」章を用意し、「まだ相談中です」と答えることを**明示的に許可**（未定を捏造で埋めさせない）③オフトピック質問には「その質問は今回のページ作成には関係ありません」とやんわり指摘し、advice側で「なぜずれているか・代わりに何を聞くべきか」を指導。
- **判定の劣化運転**: モデルは優先度リストを順に試行。429エラーで以後ローカル判定に切替、5xxで60秒クールダウン、**AI成功時もローカルキーワード判定と和集合**。AIが死んでも授業は止まらない。
- **相手役の言語統制**: N4語彙・1回1〜2文・ですます・訂正禁止・聞かれたことだけ答える——「賢すぎるAI」を意図的に制限する。

**AIへの指示（新教材でAI対話を組むとき）**:
> AI応答は必ず {answer, feeling, advice} 型で構造化し、responseSchemaで強制すること。相手役プロンプトには①正解データ（会社情報・事実リスト）②未確定事項と「まだ決めていない」と答える許可 ③話し方の統制（N4・短文・訂正禁止）④意図的な曖昧さの2段階 ⑤学習者の良い行動への感情反応ルール——を含めること。APIキーなしでも教材の前半（調査・メモ）が成立するように作り、API障害時のローカル判定フォールバックを必ず用意すること。

**アンチパターン**: ①AIが要件を全部一気に喋ってしまう ②AIが会話の途中で先生に変身して文法訂正を始める ③会社情報にないことを聞かれて、それらしい嘘を創作する ④API障害＝教材停止。

### P13. 教師運用と「実務成果物」への到達を設計に含める

**なぜ効くか**: この教材は自習アプリではなく、**教室のブレンド型授業の部品**である。教師がペースを握れること、学習の証拠が残ること、最後に「作った物」が手に残ることが、プログラム全体の説得力を作る。

**実装例**:
- **パスワードペーシング**: 先生が口頭で伝えるパスワードで次のセクションが開く。パスワード自体に遊びがある（上司の名前 `tominagasan`、学習内容の復習 `なるほど`）。解錠状態はlocalStorageに保存され再訪時は開いたまま。
- **GAS（Google Apps Script）への成績送信**: 名前・チーム・セッションID・全解答・スコアがスプレッドシートに飛ぶ。「ゲーム的進捗はローカル、評価は教師のシートへ」の二層。
- **成果物で終わる**: 連絡文（PDF出力→紙で提出・添削）、議事録、要件整理書、ペルソナ3体、サイトマップ、技術選定の理由書、Figma/Miroワイヤーフレーム、そして模範解答との**差分比較**。しつもんゲームの最終レベルでは、ヒアリングを完走すると**完成した要件定義書全文**（目的/ペルソナ/ユースケース/MoSCoW/画面/データモデル/非機能/対象外）がごほうびとして表示される——**ゲームの報酬が実務文書**。
- **口語→文書語の翻訳見本**: 結果画面の要件定義書は、顧客の「返事がたいへんで…」が「返信に毎日約1時間かかっている。この時間をなくしたい」に翻訳されている。学習者は自分が聞き出した言葉が文書になる瞬間を見る。

**AIへの指示**:
> 教材には必ず①教師が進行を制御できるゲート ②成績・成果物が教師に届く送信経路 ③最後に手に残る実務成果物 ④模範解答との比較の場——を含めること。模範解答は必ず最後まで隠すこと。

## 4. 作者が何度も修正させたポイント集（＝AIがやりがちな失敗カタログ）

実際の指示書（`質問ゲーム_最終指示書_完全版.md` ほか）と実装の差分から抽出した、**過去に人力で何度も直させた箇所**。新規発注時はこのリストを「禁止事項」としてプロンプトに貼ること。

1. **「日本語が拙い＝能力が低い」描写の禁止**。キャラ「田中優太（説明が苦手な人）」は全廃され、「ニャムさん——コンティニュー社からの出向エンジニア。**コードは優秀、日本語はN4程度を勉強中**」に差し替えられた。指示書原文:「言語が苦手＝能力が低い、という描き方は禁止」。学習者が自己投影するキャラの尊厳は絶対に守る。
2. **概念ラベルを学習者に見せない**。「クローズドクエスチョン」「オープン」等の用語は「UI・セリフ・フィードバックに一切出さない（教師向け資料のみ）」。※現行実装のブリーフィングスライドに一部残存しており、検収項目でもある。
3. **ヒントで答えを言わない**。「2回目のヒントは、完成した答えではなく、学生が自分の内容を入れられるパターン例文にする」。
4. **UIメタ用語を画面に出さない**。「『表裏』という言い方は画面上には出さない」。学習者が見るのは世界（カードをめくる）だけで、実装概念は見せない。
5. **「不正解」「間違い」の全面禁止**（P8参照）。造語も禁止——「造語は使わず、一般的な日本語を使う」。
6. **タップ選択式に逃げない**。「タップ選択式の出題は使わない」（音声質問が核の教材で）。
7. **迫ってくる敵を差し替えない**。「迫ってくるのは、必ずIT用語そのものにする」（DATA DIVE）。ビジュアル刷新でも「ゲームロジック・データ・5モードは一切変えない」という関心の分離。
8. **判定を学習者に不利にしない**。曖昧な質問で消去法の✕を付けない（「誤消去は学習を壊すため」）、表記ゆれ全許容、AI判定とローカル判定の和集合。
9. **1画面に複数目的を詰めない**。1画面1目的（聞く前の準備／聞く／書く／確認する／ロールプレイ）。
10. **画像内に重要テキストを閉じ込めない**。重要な日本語はHTML本文に置き、画像には場面・表情・関係性を担当させる（ルビ・ポップアップ・読み上げが効かないため）。
11. **ルビHTMLと判定用プレーンテキストの混同**。テンプレートリテラル内に `` ` `` と `${` を入れない、`fact/persona/keywords` はプレーン、という規律をスキーマで守る。
12. **心理的安全の演出まで文書化する**。まなびの島の設計JSONには「叱責系の演出は一切無し、失敗してもコインは減らない」「不快なブザー禁止」「純黒・純白は使わない」まで書かれている。**トーン＆マナーは実装者の裁量に任せず、明文化する**。

## 5. 教材1本の制作レシピ（AI発注用の標準手順）

### Step 0. 到達目標を1文で書く
「この教材のあと、学習者が日本のIT職場で（誰に／どの場面で／何を）できるようになるか」。成果物名も決める（連絡文1本、要件定義書1枚、バグ票1件…）。

### Step 1. 世界に場面を足す
新しい会社・キャラを乱造しない。ネクストメイクの世界（ヘンディ先輩・藤木さん・既存顧客）に新しい案件・新しい相手を1人だけ足す。相手には①人間的動機 ②数字のプロフィール ③癖（教育目的から逆算した1つだけ）を与える。

### Step 2. 隠れ要件（学習ターゲット）を10個構造化する
why×1-2 / who / what×3 / scope（やらないこと） / money / when / how を基本形に、「聞かれるまで言わない情報」を10個定義。各項目に判定用キーワード（漢字かな両方・3語以上）と「こう聞いてみよう」ヒント例文を付ける。

### Step 3. 分散ヒントの調査素材を作る
模擬メディア（SNS・古いサイト・チラシ・記事）に、要件の伏線を埋める。**秘匿情報（予算等）は書かない**。読解確認クイズ3問（答えは必ずページ内）を付ける。

### Step 4. 語彙6語を先出しする
直後の会話で相手が実際に使う語から選ぶ。語・読み・英語・実務例文の4点セット。**この6語がそのまま単語ゲーム（DATA DIVE）の新ステージデータになる**。

### Step 5. インプット→変換→産出の階段を組む
P6の階段テンプレートに沿って、選択式は読解確認のみ・産出は自由入力/音声、で構成。自由入力の前に足場（テンプレチップ・型文・2段階ヒント）。

### Step 6. AI相手役を書く（AI対話がある場合）
P12のプロンプト構成（正解データ・未確定の答え方・話し方統制・2段階の曖昧さ・感情反応ルール・answer/feeling/advice分離・responseSchema・フォールバック）。ペルソナは既存の「10か条」契約に従い、癖は第5条スロットの差し替えのみ。

### Step 7. フィードバックと報酬を書く
P8の語彙規律とP2の開示演出。星は「合格ラインは低く、上限は高く」。未達成→「つぎはこれを聞いてみよう」＋例文。

### Step 8. 成果物と模範解答を作る
学習者の口語成果が実務文書語に翻訳された見本を用意し、パスワードゲートの先に置く。差分比較の観点リスト（情報の抜け漏れ／順番／読み手が次にすること／自然な表現／短く明確か）を添える。

### Step 9. 検収する
「7. 品質チェックリスト」＋「4. アンチパターン集」で通し読み。**最後に必ず「N4のカンボジア人学生」のペルソナで最初から最後まで通しプレイする**（既存設計書の検収規律）。

## 7. 品質チェックリスト（検収用）

**役割と物語**
- [ ] 学習者が最初の画面で「自分は誰で、なぜこの行動をするか」を理解できる
- [ ] 既存世界（ネクストメイク・既存キャラ）と矛盾しない
- [ ] 相手役に人間的動機と「癖」（1つだけ）がある
- [ ] 学習者の母国・強みが活きる場面が1箇所以上ある

**リアリティ**
- [ ] 数字（価格・人数・頻度・予算・納期）が業種・規模に整合している
- [ ] 納期が事業イベント駆動になっている
- [ ] 実在技術名が正しく使われている
- [ ] 制約の網が結論の必然性を作っている（正解の丸暗記にならない）

- [ ] 調査で得る情報と質問で得る情報が分離され、秘匿情報が模擬ページに漏れていない
- [ ] 調査素材に、後で回収される伏線が1本以上ある
- [ ] 調査クイズの答えがページ内から引ける

**階段と産出**
- [ ] 聞く/読む→拾う/埋める→構造化→産出の階段がある
- [ ] 選択式が読解確認以外に使われていない
- [ ] 自由入力の前に足場（例文・型文・2段階ヒント）がある
- [ ] 最後に実務成果物があり、模範解答（ゲート付き）と比較できる

**日本語の足場**
- [ ] 全漢字にルビ（表示系）。判定・AI用はプレーンテキストで別管理
- [ ] N4超語彙に英語補助。語彙6語の先出しと会話内での回収

- [ ] 表記ゆれ（漢字/かな/カタカナ/ローマ字/全半角）を許容する判定

**フィードバックと感情**
- [ ] 「不正解」「間違い」が全文書に存在しない
- [ ] 0点でも肯定で終わり、未達成が「次に試す行動＋例文」に変換される
- [ ] ヒントが答えを言っていない（穴あきパターン文まで）
- [ ] 相手役AIが学習者の日本語を訂正していない
- [ ] 概念ラベル・UIメタ用語が学習者向け画面に出ていない
- [ ] キャラ描写に「言語力＝能力」の混同、威圧、恥をかかせる構図がない

**システムと運用**
- [ ] answer/feeling/advice が responseSchema で強制されている
- [ ] AIが会社情報にないことを創作しない（未確定の答え方が定義済み）
- [ ] API障害時のフォールバック（ローカル判定・劣化運転の文言）がある
- [ ] 教師ゲート（パスワード）とGAS送信、localStorage進捗がある
- [ ] APIキー・トークンがフロントエンドにハードコードされていない
- [ ] スマホ（375px幅）で通しプレイできる
- [ ] **N4のカンボジア人学生ペルソナで通し読み・通しプレイをした**

## 8. まとめ — この教材の核心を1段落で

この教材群の質は、情報量ではなく「**現実の仕事に近い状況を、失敗しても学びが続く形で体験させる**」ことにある。学習者を当事者にし（P1）、謎と箱で引き込み（P2）、ディテールの網で案件を本物にし（P3〜P5）、階段の最後を必ず産出で終え（P6）、感情で動機づけ（P7）、失敗を次の行動に変換し（P8）、ゲームのルール自体を教訓にし（P9）、日本語の足場を重ね（P10〜P11）、AIを相手役とコーチに分けて統制し（P12）、教師の授業と実務成果物に着地させる（P13）。——「やさしくする」と「実務から遠ざけない」の両立。これが、最初はモチベーションが低かった学習者が楽しみながらN3を目指すようになった理由であり、新しい教材が守るべき水準である。
