# ゲーム導入オンボーディング設計 — タイトル・性格診断・マップTOP

**作成日**: 2026-07-25
**位置づけ**: ユーザー提供のUIモックアップ5枚（タイトル／チュートリアル設定／性格診断／結果／マップ）を正とする画面仕様。
ビジュアルトークンは `04_ビジュアルテーマ.md`・`globals.css` を基盤に、モックアップの豪華なゲームUI表現を上乗せする。
文言は `01_理解設計ガイド.md` の規律（禁止語・N4・ふりがな）に従う。

## 0. 理解設計（作る前の3行）

1. **前提**: 生徒はスマホゲームの「タイトル→設定→マップ」の流れを知っている。Googleログインも見たことがある。
2. **新情報**: 「性格診断で自分に合うパートナー（ネクマックス）が決まる」こと。一度に入れる新概念はこれ1つ。
3. **つまずき予測**:
   - 質問の日本語が読めない → 「やさしい日本語／日本語／English」の3言語トグルを診断画面に置く。
   - Gemini APIキーが何か分からない → 必須にしない。「あとから せっていできます」を明記し、スキップ可能にする。
   - ログインの理由が分からない → 「がんばった きろくを のこすため」と伝え、Googleログインを必須にする。

## 1. 全体フロー

```
/            タイトル画面「ゲームを始める」
  └→ /welcome ステップ1: チュートリアル＋せってい（Googleログイン必須・なまえ必須・Geminiキー任意・性別必須）
       └→ ステップ2: ネクマックス性格診断（20問・3択・3言語）
            └→ ステップ3: 結果（あなたに合うネクマックス）→「はじめる」
                 └→ Supabase profiles に保存
                      └→ /map マップTOP（3分割縦スクロール＋日本固定ゴール帯／カード表示切替）
```

- プロフィール保存済みならタイトルのメインボタンは「つづきから」（→ /map）。「もういちど せっていする」の小リンクで /welcome へ。
- 旧 `/`（home-shell）は廃止し、/map が新TOP。`/tutorial`（6ステップ紹介）は残すがメイン導線から外す。
- ログインの redirect は `/auth/callback?next=/welcome`（ログイン後ウィザードに戻る）。
- `/welcome` でセッションと既存プロフィールが確認できたユーザーは、診断済みとして即 `/map` へ移動する。
- `/map` はセッション必須。セッション切れは `/welcome` に戻し、再ログイン後は既存プロフィールを取得して `/map` へ復帰する。

| `email` | text unique | トリガーで認証ユーザーから設定 |
| `display_name` | text | マップで使うなまえ |
| `gender` | text | `male` または `female` |
| `personality_type` | text | `leader`／`idea`／`heart`／`challenge` |
| `answers` | jsonb | 20要素の `"yes"`／`"neutral"`／`"no"` |
| `scores` | jsonb | 4軸それぞれ0〜10 |
| `is_admin` | boolean | 許可メールをトリガーで判定 |
| `created_at` / `updated_at` | timestamptz | 作成・更新日時 |

| localStorageキー | 内容 |
|---|---|
| `nexmax.profile.v2` | `{ displayName, gender, type, scores, createdAt }`。表示用キャッシュのみ |
| `nexmax.geminiKey` | Gemini APIキー（この端末だけ。サーバ送信・DB保存をしない） |
| `nexmax.mapView` | `"map"` \| `"cards"` |

- 旧 `nexmax.profile.v1` は読まず、削除する。
- マップ表示中はDB取得を正とし、取得完了まではv2キャッシュで描画する。
- 保存失敗時は「ほぞんに しっぱいしました。でんぱを かくにんして、もういちど おしてね。」を表示する。

正データは `public.profiles` に保存する。RLSにより本人は自分の行だけselect/insert/updateでき、`is_admin=true` の管理者は全行select/update/deleteできる。`email` と `is_admin` はトリガーで `auth.users` から強制設定する。
