# 検収ルーブリック（証拠必須）

**使い方**: レビューエージェントは1回の実行で**1セクションだけ**を担当する（注意の希釈を防ぐ）。各項目は「質問」に対して**該当箇所の引用（ファイル名＋行 or フィールドパス）を証拠として**回答する。引用できない「合格」は無効。違反を見つけたら勝ち、というスタンスで読む。感想・褒め言葉は不要。

出典: `01_理解設計ガイド.md` の13原則と品質チェックリスト。機械検査（`npm run lint:content`）で落ちる項目はここに含めない。

**R9〜R11 は 2026-09-10 に足した。** R1〜R8 が「教材1本の中」しか見ておらず、
**並び順・原典との差分・設問の自立・日本語の通り**が どの目にも 入って いなかったため
（報連相「報告」の 立て直し。台帳 #363）。

| # | 質問 | 合格条件 |
|---|---|---|

| R1-4 | 学習者の母国・語学力が強みとして扱われる箇所はあるか。あれば引用せよ | 任意（シリーズ内に1箇所あればよい） |

## R9. 順路と 移植（ステージの 並び・原典との 差分）

**教材を 足した／並べ替えた／旧アプリから 移植した ターンでは 必ず 1体 立てる。**
R1〜R8 は すべて「教材1本の 中」を 見る。**教材と 教材の あいだ**を 見る 項目が
どこにも 無かったため、2026-09-10 に「答え → 問い」「まだ 会って いない 人の 説明」
「同じ 音声の 3連」が 誰にも 止められずに 出た。

| # | 質問 | 合格条件 |
|---|---|---|
| R9-1 | `contents` を順に並べ、各教材が前提とする語・人物・枠組みを引用せよ | すべて「前の教材まで」に出ている。未登場の人物・語の説明は違反 |
| R9-2 | 問い（考えさせる箇所）と、その答えの位置を対で引用せよ | 答えが問いより後ろにある。同一画面で問いの直下に答えがあれば違反 |
| R9-3 | 同じ素材（音声・台本・図）を使う教材を列挙せよ | 3本以上連続していない。2本目に新しい課題があることを引用で示す |
| R9-4 | 学習者に見せる枠組み（型・部品・パターン）をすべて列挙せよ。**絵の中の字も数える** | ステージ内で1つ。文・絵・練習・ゲームで同じことばを使っている |
| R9-5 | ステージの description が示す終わりと、`contents` の最後は一致するか | 一致する |
| R9-6 | 関門にならない位置（`gates: false`）に置かれた課題を列挙せよ | いちばん頭を使う課題が素通りできる位置に無い |
| R9-7 | **移植のとき**: `node scripts/diff_port.mjs <旧URL> -- <新JSON>` の出力を貼れ | 「★新しく書かれた文」が1行ずつ説明できる。**因果の接続詞（ですから・だから）と英語の添え（Fact / Boss 等）を落としていない** |
| R9-8 | 仕組み（パスワード・ゲート・伏せ字）を外した箇所を引用し、その仕組みが担っていた学習上の役割と、引き継ぎ先を示せ | 引き継ぎ先が具体的な教材・画面として存在する。「ステージの関門にまかせる」は引き継ぎ先ではない |
| R9-9 | 既存の顧客・案件・キャラを使っている箇所を列挙し、**それが初めて出るステージ**を示せ | すべて**このステージより前**に出ている。**先のステージの初出を先取りしていたら違反**（後の教材を壊す） |
| R9-10 | 名前のある登場人物の立場を引用せよ | 学習者から見て**全員が先輩**。ミス役は登場人物ではない架空の人が担っている |

## R10. 設問が 単独で 成り立つか

2026-09-10 の 指摘:「最初に 状況についての 説明や 何を すれば いいかの 説明が ないまま、
ヒントを 開けないと 意味が わからないとかいう 最悪な 事態」。**ヒントは 足場であって
前提では ない。**

| # | 質問 | 合格条件 |
|---|---|---|
| R10-1 | 各設問について、**ヒントを閉じたまま**答えられるかを判定せよ | 場面・役・何を書くかが、設問文か直前の画面にある |
| R10-2 | 産出（`free` / meeting）の直前に、学習者に与えられている状況を引用せよ | 引用できなければ違反。`intro` が空の quizset は違反 |
| R10-3 | 設問文とヒント文の難しさを比べよ | 設問文のほうが難しい（＝ヒントを見て初めて設問が分かる）ものは違反 |

## R11. 日本語が 文として 成り立つか

機械検査（`lint:content`）は **禁止語・ふりがな・スキーマ**しか見ない。
**意味の通らない文は素通りする。** 2026-09-10 の実例:「💡 れいに できる こと」
（「例：できること」を分かち書きにするとき助詞を足し、別の意味の文になっていた）。

| # | 質問 | 合格条件 |
|---|---|---|
| R11-1 | 見出し・ボタン・ヒントの題を全部引用し、**日本語として読めるか**を1つずつ判定せよ | 助詞が正しい。体言止めの見出しに助詞を足していない |
| R11-2 | 数を数えている表示を引用せよ | 「〜つ」は10まで。11以上は「〜こ」等に替えている |
| R11-3 | 画面に出る語のうち、学習者が初めて見る語を列挙せよ | すべて `content/vocab` にあるか、その場で意味を添えている |
