## 0. 位置づけとプログラムの順番

```
ログイン
→ マップ画面: スタートの立札に学習者じしんの分身（ネクマックス）が立っている
→ 地点1「はじまり」（アンコールワット・order 1）
     手紙のまんが → 読み物「ちずの あるきかた」→ 返事を書く → ステージのクリアを記録
→ マップに戻る。分身が地点2へ移動する
→ 学生が自分で「かいしゃを しる」をタップして開始（自動遷移しない）
→ 地点2「かいしゃを しる」（order 2）＝ M0
→ 地点3「朝会と報告」（order 3）＝ ほうれんそう → しつもん力 → …（既存の流れ）
```

**サイン（名前を書く）は実装していない**。§2.3・§2.4 の演出はアプリ側の実装が必要なので、
現在の「はじまり」はサイン抜きで成立する構成（手紙 → 地図の歩きかた → 返事）にしてある。
返事を書くこと（`content/quizsets/hajimari_henji.json`・自由入力3問）が、サインの代わりに
**最初の日本語アウトプット**を担っている。

### 0.1 設定（ナラティブの土台）

- 学習者は Japanese IT Pathway の**1年目で日本語を勉強してきた**。ここからの区間では、ITの仕事と日本で働くために大切なことを学ぶ。
- 学習者は**ネクストメイクの「なかま」**として、社内のキャラクター（ヘンディさん・藤木さん・ニャムさんたち）と関わりながら本物の仕事を体験する。**「内定」「入社した新入社員」という設定は使わない。**
- プログラムの出口は**日本の会社への就職**。ネクストメイクを除外する言い方はしない（「ネクストメイクじゃない」等の否定表現は書かない。中にはネクストメイクに入る学習者もいてよい）。

### 0.2 既存文書との整合（読み替え注記）

- `02_拡張カリキュラム設計書.md` の「ネクストメイク1年目（研修を終えて配属された新入社員）」という記述は、本書の設定（**日本語1年修了後、ネクストメイクのなかまとして実務を体験する学習者**）に読み替える。M1〜M12の教材内容自体は変更不要。
- M1（配属初日）の自己紹介は、本導入のサイン・自己紹介の**再演**として設計する（導入＝型に出会う、M1＝型を使いこなす。スパイラル）。
- M12の採用面接は、この設定によって出口として自然になる（すでに社員なら採用面接を受ける理由がないという旧設定の矛盾が消える）。

## 1. 学生向け文言の規律（本導入で特に守ること）

過去の制作で繰り返し発生した失敗（01ガイド §4 アンチパターン2・5）への対策として、導入では次を厳守する。

1. **実物の名前だけで語る**: パスポート・チケット・場所・名前・会社。作った概念（「◯◯のみち」「2年目の道」等）を、さも最初からあったかのように学生向け文言に出さない。
2. **造語・概念ラベル禁止**。学生に「？」を浮かばせる表現は採用しない。迷ったら削る。
3. 数量表現は**「たくさん」**を標準採用（N5・教科書標準形）。「いっぱい」はキャラの砕けたセリフでのみ可。
4. 「ぼうけん」「たんけん」「クエスト」等の比喩は使わない（04テーマ §1 の文言トーン規律）。
5. フィードバック語彙はP8準拠（「不正解」「間違い」「ダメ」全面禁止）。

## 2. はじまりの漫画（3ページ14コマ）

### 2.1 形式

- データは `manga` kind（`content/manga/hajimari_manga.json`・format は `story`）。表示は現行の**横スライド（1コマずつ）**のリーダー `src/components/manga/manga-reader.tsx`（進捗しおり・ふりがなトグル・`speechInImage` 対応）。縦に全部並べる作りは「絵を流し見してセリフを読まないまま下まで行ける」ため採用しない。
- 漫画全体を**ヘンディさんからのメッセージ**として提示する。コマ1〜4はメッセージのナレーション枠（手紙風の文）、コマ5で本人が登場して名乗る。パスポートとチケットを渡すのもヘンディさん。
- テキストは**画像に焼き込まず、HTML側に置く**（ルビ合成・読み上げ・語彙ポップアップを効かせるため。01ガイド §4-10）。
- 1コマ1〜2文・1文15〜30字・分かち書き。漢字のルビはエンジンが読み辞書から合成する（手書きルビHTML禁止）。
- コマのイラストは**スタジオで生成する**（`/admin/stages` → まんが → 「🎨 絵をつくる」、または `/admin/batch`「まとめて つくる」）。画風・禁止事項・キャラ参照は `src/lib/manga-prompt.ts` が一元で付ける（手書きプロンプトを持たない）。編集判断は `docs/skills/manga_generation.md`。
- **ヘンディさんの正典は既にある**（`content/characters/hendy.json`・設定画は生成済み）。`manga.castIds: ["hendy"]` で参照する。
- 未生成のコマは `image.src` を**空にしておく**（「無い絵」の判定は src の有無。空ならバッチ生成の対象になる）。

- 2ページ目のコマ5はマップ各所にネクマックスがいるUI（04テーマのスマーフ・パターン）の予告。コマ6は**学習者じしんの分身**が地図に立つこと（`src/components/map-shell.tsx`）の予告。漫画とアプリ画面が地続きになる。

- 3ページ目のコマ3で**返事を書く**ことに橋を渡す。次のコンテンツ（読み物→返事）に手紙の文脈のまま続く。

### 2.2.1 漫画のあとに続くもの（実装ぶん）

漫画は「へんじを 書いて ください」で終わる。ステージの残り2つがそれを受ける。

| 順 | コンテンツ                             | 役割                                                                                       |
| -- | -------------------------------------- | ------------------------------------------------------------------------------------------ |
| 2  | 読み物「この ちずの あるきかた」<br>`content/articles/hajimari_chizu.json` | 地図のすすみかた3手順。**地図の上に立つ分身**の説明（アプリの見た目とデータが一致している） |
| 3  | 「ヘンディさんに へんじを 書く」<br>`content/quizsets/hajimari_henji.json` | 自由入力3問（あいさつ・名前・これからする こと）。`phase: production`・`passRate: 50`       |

3つぜんぶ終わると `markStageCleared("hajimari")` が走り、マップの分身が地点2へ動く
（`src/components/stage/content-frame.tsx`）。学生が自分で次をタップする——自動遷移はしない。

### 2.3 サイン画面 — **未実装（アプリ実装が必要）**

> 現行のコンテンツ規格（stage / manga）には「名前を書く」「地図がひらく」という**挙動を載せる場所がない**。
> スタジオで作れるのは漫画・読み物・問題・音声までで、この体験は別途アプリ側の実装になる。
> **いまの「はじまり」はサイン抜きで成立している**（§2.2.1）。サインを足すときは、返事を書く問題の
> **前**に差し込む（手紙 → サイン → 地図の歩きかた → 返事）。漫画2ページ目コマ3の
> 「パスポートには、あなたの 名前を 書いて ください」がその予告として既に置かれている。


- パスポートの1ページ目が開き、**名前を入力してサインする**。これが本プログラム最初の日本語アウトプットであり、**日本語入力（IME）チェックを兼ねる**。
- **カタカナ推奨・どの表記でも受理**（P8: 判定を学習者に不利にしない）。ローマ字入力からのカタカナ候補チップを足場として表示する。
- 入力に困った学生向けに「にゅうりょくの ヘルプ」（ローマ字→かな対応表）への導線を置く。
- サイン完了 → §2.4 のクライマックス演出へ続く。

### 2.4 メッセージが地図にひらく（クライマックス演出）

導入の最大の見せ場。**ヘンディさんのメッセージ（手紙）が、そのまま「まなびマップ」に変わる**。サイン（産出）の報酬として発火する（04テーマ §5「演出は学習行為の報酬に紐づける」）。

演出シーケンス:

1. **サイン着地**: 入力した名前がパスポートに**スタンプのように押される**（スプリングで scale 1.4→1.0 の着地＋紙の凹み影）。
2. **チケット**: パスポートにチケットがスライドインして差し込まれる（軽い揺れで止まる）。
3. **展開**: ヘンディさんのメッセージの便箋が画面中央に浮かび、**折り目から3Dで広がって、そのまま画面いっぱいの「まなびマップ」になる**（perspective＋rotateX の折りたたみ展開）。学生向けテキストはここでは足さない——手紙が地図に変わることは視覚だけで伝わる（説明の言葉を増やさない）。
4. **道が伸びる**: 白い道が SVG の pathLength アニメーションでスーッと描かれ（マップ既存実装の流用）、「かいしゃを知る」が点灯。遠くに東京🗼が見える。
5. **一言**: ネクマックスの吹き出し「つぎの 場所を タップして、はじめましょう。」（§4の導線に接続）。

実装ノート:

- 基盤は **motion/react**（チュートリアル・マップで使用中）のスプリング＋AnimatePresence。折りたたみ展開は CSS 3D（`perspective` / `rotateX` / 折り目に置いた `transform-origin`）を段差（stagger）で開く。
- ステージ→マップの画面遷移は現実装ではフェード。React の `<ViewTransition>` による強化は `experimental.viewTransition` の有効化とセットで別途検討する（設定変更を伴うため本演出の必須条件にしない）。
- `prefers-reduced-motion` では演出を全停止し、クロスフェードのみに落とす（04テーマ §5 の規律）。
- **スキップ時はこの演出を発火しない**（マップを静かに表示する。演出はサインの報酬であるため）。

## 3. パスポートとチケット

| 実物       | 役割                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| パスポート | プロフィール（サインした名前）＋スタンプのページ＋作品（成果物）の一覧。モジュールを終えるたびにスタンプが押される。**1年後、面接で見せる「わたしのがんばり」の記録になる**（02設計書 M12 のふりかえりシート・ポートフォリオ構想とそのまま接続する） |
| チケット   | マップの場所へ行けることの物語的表現。UI上は停留所の解錠と同義（新機能ではなく、解錠の言い換え。学生向け文言では「チケットで 行ける ように なった」等に使う） |

- スタンプ・星の報酬演出はエンジン共通部品（03方針 §1.2 報酬演出）を使う。
- パスポートのデータは `artifacts` / `progress` テーブルに載せる（03方針 §3）。パスポート画面は本導入では最小実装（名前＋スタンプ1個が見えれば足りる）でよい。

## 4. 置き場所と導線（現行実装に合わせた版）

- **URL**: ステージIDがURLの1段目になる（`src/lib/stage-routes.ts`）。はじまりは `/hajimari`、漫画は `/hajimari/manga`。
  `/stages/...` や `/welcome` という置き方はしない（`welcome` は `RESERVED_STAGE_IDS`＝ステージIDに使えない）。
- **マップ**: 公開ステージを `order` の昇順に並べたものが地図（`src/lib/map-data.ts`）。はじまりは `order: 1`。
  ステージが立つ土地（背景画像）は `stage.area` が持つ（未設定だと地図が空色の帯になり `checkStageOrder` が警告する）。
- **何度でも読める**: ステージはマップに常設される。漫画リーダーは最終到達コマをしおりとして持つので、
  途中からでも読み直せる。「1回だけ出す案内」のような画面状態は持たせない（データに置き場所がない）。
- **初回の自動再生はしない**（現行の初回導線は `/welcome`（性格診断）→ `/map`）。
  導入を初回に自動で見せたいなら、それは**アプリ側の導線実装**として別に決める（§2.3 と同じ扱い）。
- **公開まで**: `status` は最初 `draft`。漫画の絵が入り、ふりがな警告が消えてから `published` にする。

## 5. M0「かいしゃを知る」

### 5.1 到達目標（1文）

> 会社のWebサイトを見て「なにを作る会社か・お客さまはだれか・どんな人が働いているか」を調べ、ヘンディさんに日本語で説明できる。

これは就活でそのまま使う**企業研究の型**の第一歩である。面接前に会社を調べるスキルの練習を、招待してくれた会社＝ネクストメイク自身を題材に行う。

### 5.2 物語（ミッション）

ヘンディさんからのミッションチャットで始まる:

> ようこそ、ネクストメイクへ！
> ところで あなたは、わたしたちの 会社の こと、どのくらい 知って いますか？
> 会社の ホームページを 見て、しらべて みて ください。
> あとで、わたしに おしえて くださいね。

社員本人に会社のことを報告する、という軽い逆転（P1: 学習者が説明する側に立つ）。

### 5.3 学習フロー

```
ことば先出し（10語）                                          … ✅ stage23_kaisha
→ 読み物「かいしゃの しらべかた」（3つの目・どのページ・はたらきかた3つ）… ✅ kaisha_shirabekata
→ 読解クイズ（読み物の確認・5問）                              … ✅ kaisha_shirabekata_check
→ しらべる（本物のWebサイトを グループで 自由探索。3つの目カード）… ⬜ 未実装（§6の突き合わせが前提）
→ サイトの読解クイズ3問（§6.1）                                … ⬜ 未実装（同上）
→ ヘンディ会話チェック（ポイントボード。1人1ポイント以上 発話） … ⬜ 未実装（同上）
→ スタンプ＋会話結果カード                                     … ⬜ 未実装
```

**3つの目・ページの見かた・はたらきかた3つを「読み物」として先に置いた**のは、実サイトの探索が

### 6.2 実サイトへの通信について（環境の設定が要る）

クラウド実行環境（Claude Code on the web）は**送信先の許可リスト**で外部通信を絞っている。
既定の `Trusted` では `nextmake.site` に届かない。届かないときの症状はこれ:

> `HTTP/2 403` ＋ `x-deny-reason: host_not_allowed`
> `Host not in allowlist: nextmake.site. Add this host to your network egress settings to allow access.`

**HTTPクライアントの選び方の問題ではない。** curl（プロキシ経由・迂回・IP直打ち）も
headless Chromium も同じところで止まる（BeautifulSoup でも Playwright でも同じ）。
DNSは引ける（162.43.105.152）ので、名前解決を疑っても時間を捨てるだけ。

直し方: claude.ai/code のメッセージ欄の上にある雲アイコン → 環境の歯車 →
**Network access** を `Custom` にして **Allowed domains** に `nextmake.site` と `*.nextmake.site`
を1行ずつ。**`Also include default list of common package managers` にチェックを入れる**
（外すと npm・GitHub まで止まってビルドが通らない）。`Full` にしてもよい。
**保存しても走っているセッションには効かない**ので、新しいセッションで作業する
（2026-08-07 の実施時は `Full` に変更して、そのセッション内で通るようになった）。

**WebSearch（検索インデックス）は許可リストと無関係に使える。** ただし要約であって逐語ではなく、
**サイトが変わっていても変わったことを教えてくれない**（今回それで理念を取り違えた）。
学習者に見せる会社の文は、必ず実サイトから取る。
