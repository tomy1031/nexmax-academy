1結論

ご指摘は全て事実でした。そのうえで、原因は「文言が難しい」ことではなく、 教材の並び順が、学習者の頭の中の順序と逆になっていることです。 旧アプリは 謎 → 壁 → 答え の順でしたが、現状は 答え → 謎の形をした復習 になっています。

1.1 3行でいうと

  1. 答えが問いより先に置かれている。「会社の階級」も「報告のコツ」も「一番大切なのはチームワーク」も、 学習者が考える前に画面に出ています。だから最後の「調べ学習」に、調べる理由が残っていません。
  2. 藤木取締役に会う前に、藤木取締役の説明が始まっている。 旧アプリでは「藤木さんに報告する場面を聞く → だから階級を知りたくなる → 調べる → 答え合わせ」でしたが、 現状は「階級の図を見る → 7画面あとに調べさせる」になっています。
  3. 覚えるべき枠組みが、同じステージに3つある。 文は「3つのパターン」、絵は「件→結論→事実→お願い」、済スタンプは「こえかけ・じじつ・みこみ・おねがい」。 3つとも別のことばです。

1.2 やること（提案）

#やること効き目
A順路を組み直す（8本 → 10本。階級を「調べる → 答え合わせ」の位置へ戻し、問いと答えの間に書く壁を入れる）ご指摘の「順番」「いきなり階級」が同時に解ける

3.3 役割ごとに何が失われたか

学習の役割旧アプリ現状失われたもの
大きな問い「日本の会社で一番大切なことは何ですか？」→ 壁 → 答え 冒頭に "日本の 会社で 一番 大切なのは チームワークです。"／その後で見出し "なぜ 報告を するの？" → "答えは「チームワーク」です。" 考える時間。問いが「答えの復唱」に降格した
自分で作る場Q1〜Q3を考える → 壁 → 解説ページでA1〜A3 Q1の直後、同じ画面に "最初に 声を かける。…「今、お時間 よろしいですか」と 許可を もらいます。" 入力欄と、答えとの間の壁。3問とも読み物になった
報告パターン3つ解説ページで中身を説明 "3つの パターンを 使い分ける。終わった 報告・困って いる 報告・気づいた ことの 報告です。" の1行だけ 中身が丸ごと。8本のどこにも「困っている報告」の言い方が無い
藤木さんの紹介リスニング直前に「お客様と直接話しています。ですから、問題があっても藤木さんがお客様にすぐ確認してくれます」 記事の最後に "次の リスニングに 出て くる 藤木さんは「取締役」です。" 「だから」の因果。報告が届くとお客様に届く、という報告する理由そのもの
階級の謎調べ学習（謎）→ 次ページで階級の図（答え合わせ） 記事の中に階級の図と答え → 7画面あとに調べ学習 調べる理由
カンボジアとの比較調べ学習で自分が考える 記事が先に "日本も カンボジアと 同じで、目上の 人を 大切に して、ていねいに 話します。" と断定 比べる余地。「同じ」と結論を出したあとで「違いを調べろ」と言っている
調べたあとの着地ボタン「次のページへ」でアプリ内の階級ページへ戻る "答えを 書く シートは 新しい タブで 開きます。" → 外部シートで終了 帰り道。書いた答えに誰も返事をしない
設計上の発見：パスワードという不便な仕掛けは、実は「考える時間を強制的に作る装置」でした。 それを外したのは正しい判断（ご指示どおり）ですが、装置が担っていた役割の引き継ぎ先が決まっていませんでした。 これが今回の壊れ方の本体です（8章 原因1）。

4何が どのように 学習を阻害しているか

ペルソナ3体（N5 / N4 / N3）が実際に詰まった所を、重い順に12件。「読みにくい」ではなく「理解が壊れる」ものだけを載せています。

阻害1 最重 答えを読んでから、その答えを探させている

現象：記事の一番上に "日本の 会社で 一番 大切なのは チームワークです。"（hero の lead）。 少し下に見出し "なぜ 報告を するの？"、その直後に "答えは「チームワーク」です。"。

なぜ理解が壊れるか：最初の3秒で「このページは自分に何も聞いてこない」と分かってしまいます。 以降、学習者は読み飛ばす姿勢に切り替わり、そのあとに来るQ1〜Q3も読み物として流れていきます。

N3ペルソナ：「答え→問い→答えの順。最初の3秒でこのページの読み方が決まってしまう」

阻害2 最重 考える前に、答えが3センチ下にある

現象："あなたは 最初に どんな ことばを かけますか。"（Q1）の直後に、見出し「報告の コツ」と "最初に 声を かける。忙しい 人に 話しかける ときは、「今、お時間 よろしいですか」と 許可を もらいます。"。 書く欄も、押して開くボタンもありません。

なぜ理解が壊れるか：自分の言葉を一度作ってから見本を見ると、差分が学習になります。 見本を先に見た場合、脳は「知っている」と判定して記憶に残しません（考えた人だけが損をする作り）。

付随する壊れ：Q3 "ITの 仕事では ほかに どんな 報告が 必要だと 思いますか。" だけは、 答えがステージのどこにもありません。3問のうち2問だけ答えが即出るという、非対称な形になっています。

阻害3 最重 覚える枠組みが3つある（文・絵・ゲームで全部ちがう）

どこいくつことば
記事の文（steps）3つ声をかける／結論から／3つのパターン（終わった・困っている・気づいた）
記事の絵 keypoint.webp4つ件 → 結論 → 事実 → お願い（画面いっぱいの大きな字）
済スタンプ4つこえかけ・じじつ・みこみ／あたり・おねがい
クエストの中—同じものを「札（ふだ）」と呼ぶ

なぜ理解が壊れるか：docs/constraints.md の指定どおり 「文章では理解できない人がいる前提。絵で分かるようにする」のなら、学習者が最も強く受け取るのは 絵の「件→結論→事実→お願い」です。ところがその4語は、以後どの教材でもその名前で呼ばれません。 いちばん記憶に残る枠組みが、いちばん回収されないという配置になっています。

N4ペルソナ：「文は3つ、絵は4つ。どちらを覚えるのか分かりませんでした。」
N5ペルソナ：「3つと4つ、どっちが本当か分からなくなった」

阻害4 最重 階級の図と本文で、取締役の名前が違う

現象：本文は "次の リスニングに 出て くる 藤木さんは「取締役」です。"。 そのすぐ上に置かれた図 houkoku_hierarchy.webp には、「取締役 － 藤田さん (Director - Mr. Fujita)」と大書されています。 さらに図の会社名は「株式会社どうぶつ商事」、社長は「松井社長」（このアプリの別ステージに実在する別キャラクター）、 登場人物は全員動物です。

なぜ理解が壊れるか：学習者は「藤木さんと藤田さんは同じ人か、別人か」を判断できません。 N4ペルソナはこれをステージ全体で一番混乱した点に挙げました。

公平な注記：この図は旧アプリの原本とピクセル単位で同一で、名前の食い違いは旧アプリから引き継いだものです。 ただし旧アプリでは、この図は最終ページに単独で置かれ、藤木さんの名前とは並んでいませんでした。 移植の際に「藤木さんは取締役です」という文を図の隣に新しく足したことで、衝突が生まれています。

阻害5 重 会う前の人を説明している（階級の位置）

現象：記事の末尾で、まだ声も聞いていない藤木さんについて "とても 上の ポジションで、お客様と 直接 話して います。" と説明されます。

なぜ理解が壊れるか：人物の属性は、その人に会って印象ができたあとでないと結びつきません。 旧アプリが「藤木さんはですからお客様にすぐ確認してくれます」と因果でつないでいたのに対し、 現状は属性の羅列になっており、覚える理由がありません。

N4ペルソナ：「藤木さんは、ページの最後で名前を見たばかりの人です。声を聞くまで、わたしにとっては『知らない人』でした。」
N4ペルソナ（希望）：「藤木さんの声を聞いたあとに『あの人は取締役で、上から2番めです』と教えてほしいです。会う前に予告されても覚えられません。」

阻害6 重 「済スタンプ：報告の4つのパーツ」— 教わっていない分類で作業させている

問題証拠
4つのパーツをどこでも教えていない「こえかけ／じじつ／みこみ・あたり／おねがい」はこのツールと、そのリンク定義にしか存在しない
同じ音声の2回目（3本目のもんだいも同じ会話）リスニングもスタンプも "audioUrl": "/audio/hourensou/houkoku.wav"
「聞こえた瞬間に押す」と言うのに、瞬間を見ていないツールの設計コメント："音声の タイムスタンプは 持って いない。回数だけ くらべる（何秒で 押したかは 見ない）"
名前が読めない「済（すみ）」はN5の学習範囲外。「パーツ」は実装側の言い方
押し始めが分からない音声の冒頭5行はナレーション（"はじめに「報告」に ついて 話します。"）でパーツが無いのに、そう書いていない
N3ペルソナ：「答え合わせは回数を並べるだけ。いつ押したかは見ていない。つまり6回、それらしい所で押せば当たる。 これは『聞き分ける』練習ではなく『押す作業』です。」

判定：ご指摘のとおり却下が妥当です。詳細と、救う場合の唯一の条件は6章。

阻害7 重 記事が「同じ」と断定した直後に、「違いを調べろ」と言う

現象：記事 "日本も カンボジアと 同じで、目上の 人を 大切に して、ていねいに 話します。" → 調べ学習「カンボジアと日本の『報告』への考え方の違いを教えてください。」

なぜ理解が壊れるか：課題が矛盾しているため、何を書けば良いか決められません。 さらに学習者の母国について、教材が先に結論を出している形になっています。

N3ペルソナ：「カンボジア人の自分としては、自分の国の答えを先に決められた感じがして、正直いやだった」

これは docs/design/01_理解設計ガイド.md P1「学習者の母国・現地感覚が武器になる場面を埋め込む」の、ちょうど逆です。

阻害8 重 「調べ学習」のページだけ、日本語の書き方が別物

現象：アプリの全教材は分かち書き（"日本の 会社で 一番 大切なのは"）ですが、 このページだけ旧アプリのHTMLをそのまま使っているため、すきまがありません（「日本の階級をたくさん調べてみましょう。」）。

N5ペルソナ：「ここまでは ことばの間にすきまがあったのに、このページは すきまが無い。 同じN5のわたしなのに、ここだけ急に難しくなった。」

加えて、「調べ学習」「応用問題」という語自体が説明されていません（N5：「『応用』が何か知らない。やるものか、やらなくていいものか判断できない」）。 ご指摘のとおり、この語は学習者向けの画面名として不適切です。

阻害9 中 「件」が3つの教材に出て、一度も説明されない

現象：記事 "何の 件か、どう なったかを 先に 言います。"／スキット "ログイン機能の 件ですが"／ ミーティング "何の 件か、どう なったか。"。 そして content/vocab/vocabulary.json（866語）に「件」が入っていません。 辞書ポップアップも出ず、単語テストにも出ません（「事実」「結論」「取締役」「見込み」は入っています）。

なぜ理解が壊れるか：「件」は報告の型（件→結論→事実→お願い）の1番目です。 ここが空白のまま型を教えているので、型そのものが立ちません。「階級」も同じく未登録です。

阻害10 中 上司が3人入れ替わる

記事・スキット・クエスト＝富田さん（PM）／リスニング・スタンプ＝藤木さん（取締役）／ ミーティング＝ヘンディさんが上司役。 とくにヘンディさんは、リスニングでは報告する側（部下）でした。

N5ペルソナ：「同じ人がなぜ立場を変えたのか分からなくて止まった」
N3ペルソナ：「誰に報告する練習をしているのか、途中で分からなくなった」

阻害11 中 ステージの説明と、実際の終わりが違う

ステージ説明は "最後は 報告クエストで 一日を 遊びます。"。 しかし contents の最後はクエストではなく調べ学習です。

N5ペルソナ：「終わったと思ったのに、まだあった。気持ちが切れた後にいちばん難しいページが来る」

しかも調べ学習は種別が link で関門になりません（content-kinds.ts の gates: false）。 つまりいちばん頭を使う課題が、いちばん踏まれにくい位置にあります。

阻害12 中 もんだいがリスニングしか測っていない

6問すべてが音声の内容確認です。記事で読んだ「コツ」も、押した「4つのパーツ」も、1問も出ません。

N5ペルソナ：「読んだ所と押した所が、テストされない。覚えたかどうか自分で分からない」
