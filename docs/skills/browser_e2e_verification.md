# 実機検証スキル — ブラウザ自動操作でこのアプリを触るとき

**目的**: エージェント（Claude/Codex）がブラウザ自動操作で本番・staging を検証するときの作法。
**書いた理由**: 2026-08-04 の Phase B-7 検証で、性格診断20問の自動入力に失敗し
**ユーザー本人の診断データを実際に壊した**。同じ事故を繰り返さないための記録。

---

## 0. 本番の実データを操作対象にしない（最優先）

**やらかした実例（2026-08-04）**

`/welcome?retake=1` の通し確認を、**ユーザー本人のアカウントで本番に対して**実施した。
選択肢のクリックが安定せず、リトライを重ねるうちにスクリプトが全20問を「Ⓐ」で
完走・保存し、`tomy1031@gmail.com` の判定が **INTP → ENTP** に書き換わった。
元の回答は退避してあったが、`personality_results` には誤った受験記録が1件残った。

**守ること:**

- 保存を伴うフローは**検証専用アカウント**で行う。他人の（ユーザー本人を含む）
  行を書き換えない
- どうしても本人アカウントで行うなら、**先に現在値を SQL で退避**してから始める
  （`answers` / `scores` / `personality_type` / `answer_language`）
- 「読むだけの検証」と「書き込む検証」を混ぜない。ルート疎通・描画・リダイレクトの
  確認は保存の手前で止められる。**そこまでで足りるなら、そこで止める**
- 壊したら隠さず報告する。復旧手段（退避値・SQL）も一緒に出す

## 1. 実マウスクリックだけが効く。JS の `.click()` は効かない

学習エンジンのボタンは React の合成イベント＋framer-motion で動いている。

- `javascript_tool` から `element.click()` を呼んでも **state が更新されない**ことがある。
  「クリックしたのに進まない」の大半はこれ
- 使うのは `computer` の実クリック（座標指定）か、`read_page` が返す `ref_N` 経由のクリック
- **効いたかどうかは必ず画面側で確認する。** 進捗表示（「20もんの うち N もんめ」）や
  `aria-pressed` を読む。クリックの成功可否を戻り値で判断しない

## 2. カード遷移アニメーション中のクリックは吸われる

設問カードは framer-motion で横スライドしながら入れ替わる。この間:

- 退場中の旧カードと入場中の新カードが**同時に DOM にある**
- 選択肢ボタンの x 座標が**2つの値の間で交互に振れる**（実測: 545/907 ↔ 635/997）
- 前の設問の座標をそのまま使うと、**退場中のカードを叩く**（＝何も起きない、
  あるいは前の設問をもう一度答える）
- 遷移の途中はカードが透明になり、スクリーンショットが**空白に見える**

**唯一安定した手順**は、1問ごとにこの3つを1バッチで回すこと:

```
1. 直前のスクリーンショットから読んだ座標をクリック
2. 2〜3秒 待つ
3. スクリーンショットを撮る（次の座標はここから読む）
```

座標は**毎回読み直す**。使い回さない。

## 3. `window.confirm` は自動操作を止める

`/admin/users` の削除・リセットはネイティブの確認ダイアログを出す。CDP はこれで
ブロックされ、ツール呼び出しがタイムアウトする。

- 回避するなら `window.confirm` を一時的に上書きし、**検証後に必ず元へ戻す**
- 回避したこと自体をユーザーに黙っていてはいけない。「確認ダイアログを迂回した」と
  明示する（＝本来は人間が止められるはずの操作を、止まらずに実行したということ）

## 4. 画像は `loading="lazy"`。読み込み中に測ると壊れて見える

`naturalWidth === 0` を根拠に「画像が壊れている」と報告しない。lazy 読み込みの
途中を測っているだけのことがある。判定は `curl` でHTTPステータスを見るか、
十分待ってから測る。

## 5. 撤退条件 — 人に渡したほうが速い場面がある

**多ステップの手入力（20問の通し等）は自動操作に向かない。**
同じ操作で3回連続して進捗が変わらなければ、それ以上粘らない。

止めて、ユーザーに次を渡す:

- 何を押せばよいか（例: `Ⓐ Ⓐ Ⓑ Ⓐ …` の一覧）
- どこから始めるか（URL と現在の設問番号）
- 何が確認できていて、何が残っているか

人が30秒で終わることに、エージェントが10ターン使わない。

## 6. DB 側の確認は MCP で直接見る

画面の見た目より、`mcp__supabase__execute_sql` で行を読むほうが速く確実。
性格診断まわりで見る列:

```sql
select p.personality_type, jsonb_array_length(p.answers) as n_answers, p.scores,
       (select count(*) from personality_results r where r.profile_id = p.id) as history
from profiles p where p.email = '<検証用アカウント>';
```

履歴が残る仕様（07 §8.3・§8.5）の確認は、**リセット前後で `history` が減らないこと**を
見れば足りる。画面を通す必要はない。
