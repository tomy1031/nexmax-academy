# 漫画づくりのスキル — コマ割り・読みやすさ・ふりがな

**目的**: `manga` kind の教材を作るときの**編集判断**（コマ割り・セリフ・ふりがな）をそろえる。
**このファイルに書かないこと**: 画風・禁止事項・キャラ参照の渡し方は**コードが唯一の台帳**である
（`src/lib/manga-prompt.ts` の `STYLE` / `NO_TEXT` / `NEGATIVE` / `buildCharacterSheetPrompt` /
`buildPanelPrompt` / `buildMangaScriptPrompt`）。ここに写すと、片方だけ古くなって画風が割れる。
**契約**: `src/content/schema.ts`（`mangaSchema`）と `src/lib/content-checks.ts`。文章の規律は
`docs/design/01_理解設計ガイド.md`、画像アセットの手順は `docs/skills/codex_image_generation.md`。

---

## 0. 大前提（コードが守っていること。作る側が壊さないこと）

1. **絵の中に文字を描かせない。** セリフは `lines` に持ち、画面が重ねる。生成プロンプトには
   `NO_TEXT`（吹き出しは**空**で描かせる）が必ず入る。
   絵に焼き込みたい場合だけ `speechInImage: true` にする（**ふりがな入り画像は成功例がない**）。
2. **すべての漢字に、文脈どおりの正確な読みを付ける。** `furigana` に載っていない漢字が1つでも
   あると **公開できない**（`checkFuriganaCoverage`。下書きは warn・公開は error）。
3. **キャラは設定画（`character.sheet`）を参照画像として毎回渡す。** 人物は漫画の中ではなく
   `content/characters/*.json` に置き、`manga.castIds` で参照する。

## 1. ふりがなの規律 — 正確に

学習者は付いているルビをそのまま覚える。**間違ったふりがなは、間違いをそのまま教える。**

- 読みは**その文の文脈での読み**で書く: 「行けます」→`["行","い"]`／「1年間」→`["年間","ねんかん"]`
  （数字にルビは付けない）／「客先」→`["客","きゃく"]` のように**単字も必要になる**。
- **複合語と単独語の両方を登録する**（引き当ては最長一致）。「日本語」があるなら「日本」も。
- 検証は次の順で行う。**推測で書かない。少しでも曖昧なら辞書で確認する。**
  1. `npm run lint:content`（未覆いの漢字を場所つきで指摘する）
  2. `npm run measure:readability`（文長・漢字密度）
  3. ふりがなONの実画面で全コマを音読する
- ルビを書く場所は**読み辞書だけ**。ルビHTMLの手書きは `plainText` が弾く（規律2）。

## 2. コマ割りの原則

読む画面は**横スライド（1コマずつ）**（`src/components/manga/manga-reader.tsx`）。
縦に全部並べる作りは「絵を流し見してセリフを読まないまま下まで行ける」ため**やめた**。
1コマが1画面を占める前提で割る。

| 原則             | 内容                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| 1コマ1情報       | 1コマで伝えることは1つ。詰め込むなら2コマに割る                                 |
| 場面＝ページ     | 場面が変わったらページを分け、`pages[].title`（場面カード）で転換を示す         |
| 決めゴマは1場面1つ | `size: "wide"` は登場・感情のピークだけ。多用すると効かない                     |
| 「間」を作る     | `size: "tall"` は沈黙・考える時間・景色に使う                                   |
| 立ち位置の一貫   | 同一場面では人物の左右・向き・服装を変えない（コマ間の混乱のもと）              |
| 量の目安         | `yonkoma` は1ページ4コマ（起承転結）／`story` は1場面3〜5コマ                   |

## 3. セリフとナレーション

- 1コマ**1〜2文・1文15〜30字・分かち書き**。長い説明は複数コマに割る。
- キャラの声は `lines`（`speaker` は `castIds`／`characters[].id`）、地の文は `speaker: "narration"`
  か `caption`。混ぜない。
- **感情は絵（表情・構図）で伝える。** 文字で「かなしい」と説明しない。
- 語彙はN4基準。禁止語（「不正解」等）は保存時に弾かれる。国名は規律9（`checkCountryNames`）。

## 3.5 ことばの抽出 — **N5のつもりで多めに出す**（2026-08-12 追加）

絵の下に出す `vocab` は、**書いた本人が「これは分かるだろう」と思った語ほど落ちる**。
学習者は日本語1年目である。基準は「N4なら分かる」ではなく **「N5でも読めるか」**。

- **カタカナ語を必ず入れる。** いちばん抜けやすい。見た目が英語でも、
  カタカナで書かれた瞬間に別の語になる（`プロジェクトマネージャ` `プログラマー`
  `サポート` `パスポート` `チケット` `テスト` `メッセージ`）。
  英語が読める学習者でも、カタカナ表記からは元の語にたどりつけない。
- **動詞・形容詞も入れる。**「知りません」「わかりません」「はずかしい」「失敗」のような、
  文の意味を決める語を名詞だけの一覧から落とさない。
- 意味は**英語を必ず添える**。やさしい日本語だけだと、その言い換えが読めないことがある。
- 説明文そのものに漢字を混ぜない（説明が読めないと意味がない）。`lint:content` が
  ふりがな未覆いとして弾くので、かな＋英語で書く。
- 迷ったら入れる。**多すぎて困った例は無く、足りずに止まる例だけがある。**

そのコマに出てきた語だけが絵の下に並ぶ（`manga-slides.tsx` が本文と突き合わせる）ので、
`vocab` に多めに登録しても1コマの表示は増えすぎない。

## 4. 作る順番（スタジオ／`/admin/stages`）

1. 人物が足りなければ `/admin/characters` で作り、**設定画（シート）を先に生成**する。
2. ステージの「③ ながれ」から「＋ふやす → まんが」で作る（ステージに自動で紐づく）。
   別画面で作ってIDを手打ちすると、参照切れに気づくのが学習者のタップ後になる。
3. 「AIで つくる」で**わりつけとセリフ**（文字だけ）を作り、**その場で直す**。
   AI生成を一発で通さない（`docs/constraints.md`: 段階を踏む）。
4. コマごとに「🎨 絵をつくる」。同じ場面の続きは前のコマの絵も参照に足す。
5. 「したがき」で保存してふりがな警告を消し、最後に「こうかい」。

## 5. 受入チェック（1コマごと＋全体）

> **全コマを目で見る。抜き取りにしない。**（2026-08-12 追加）
> 17コマのうち6コマだけ確認して公開し、**手紙の差出人コマに別人が描かれたまま**通した
> 事故がある。生成が成功した（`ok` が出た）ことと、絵が合っていることは別である。
> とくに「人物が出るはずのコマ」「人物が出てはいけないコマ」は取り違えやすい。

- [ ] 人物が設定画と一致（顔・髪・服）。コマ間で変わっていない
- [ ] **読める文字が画像内に1つもない**（`speechInImage: false` のとき）
- [ ] 表情が友好的（怒鳴る・嘲笑・恐怖の構図がない — 01ガイド）
- [ ] 決めゴマ（wide）が場面に1つまで
- [ ] ふりがな検証（§1の3手順）を完了した — **正確に**
- [ ] `npm run lint:content` グリーン／スマホ幅（375px）で通し読みできる

1つでも落ちたら**部分修正せず作り直す**（差分を具体化して撮り直す）。

## 6. 運用

- 生成に使ったプロンプトは画像スロットの `prompt` に残る（「少し直して再生成」のため）。
- 差し替えは版を付けて `src` を切り替える（上書きしない）。
- **「無い絵」の判定は `image.src` が空かどうか**で行われる（`status` は見ない）。
  未生成のコマは `src` を書かないでおく — そうすれば「まとめて つくる」の対象になる。
