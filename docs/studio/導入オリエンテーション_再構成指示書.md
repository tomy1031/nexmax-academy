## 2. やること（優先順）

### A. 漫画12コマの絵を作る（最優先・これだけで導入が成立する）

スタジオで作る。`/admin/stages` → 「はじまり」→ ③ながれ → まんが を開く。

1. 生成の前提を確認する（`/admin/ai`）。**Codex を第一・Gemini は控え**（`docs/constraints.md`）。
   Codex ブリッジは先生PCで `npm run codex:bridge`＋合言葉。どちらも無いと生成は「じゅんびちゅう」になる。
2. ヘンディさんの設定画は既にある（`content/characters/hendy.json` の `sheet`）。**作り直さない。**
3. コマごとに「🎨 絵をつくる」。同じ場面の2コマ目以降は**直前のコマの絵も参照に足す**（背景・光・服の連続性）。
   まとめてやるなら `/admin/batch`「まとめて つくる」——`image.src` が空のコマだけを直列で埋める。
4. `docs/skills/manga_generation.md` §5 の受入チェックを1コマずつ通す。落ちたら**部分修正せず作り直す**。

**重要（二重管理の注意）**: スタジオで保存すると **DB（`studio_contents`）に版ができ、同一IDでは DB が git に勝つ**。
git のJSONを正として運用したいなら、次のどちらかに決めてから始める。
- **スタジオを正にする**: 以後 git 側の `hajimari_manga.json` は触らない（触っても画面は変わらない）。
- **git を正にする**: 生成した絵のURLだけを git のJSONに書き戻し、DB版は「けす」で削除する。
どちらにするかを**先にユーザーへ確認**する。

## 3. 守ること（機械が検査するもの）

- **JSONを足したら `npm run gen:content`**。アプリは焼き込み済みの `src/content/git-contents.generated.ts` を読む。
  忘れると `lint:content` が error（画面も変わらない）。
- **ふりがな全覆い**: 学習者が読む文の漢字は読み辞書で全部覆う。公開は error・下書きは warn。
  ステージの `area.name` / `title` は**読み辞書を持てない**ので、漢字を使わずひらがなで書く（実際に1度落ちた）。
- **禁止語**（不正解／間違いです／ダメです…）・**国名**（「タイ」禁止・ベトナム等は要確認）・**ID は kind をまたいで一意**。
- **選択式は読解確認だけ**（`phase: "production"` に choose/multi/emotion は置けない）。
- **絵に文字を描かせない**（`speechInImage: false` のまま。ふりがな入り画像は成功例がない）。
- 既存UIの**作り直しをしない**（改良のみ）。`middleware.ts` を `proxy.ts` に改名しない（規律8）。

## 4. 検収

```bash
npm run gen:content && npm run lint:content   # エラー0まで
npm run lint && npm run typecheck && npm test
npm run measure:readability                    # 30字超・漢字密度を確認
```

そのうえで**実機で通す**: `npm run dev` → `/hajimari` と `/hajimari/manga` を**375px幅**で通し読み
（ふりがなON/OFF・しおり・絵の抜け）。ブラウザ自動操作をするなら `docs/skills/browser_e2e_verification.md`
に従い、**保存を伴う操作は検証専用アカウント**で行う（本番データ事故の再発防止）。

確認URLは自分のブランチ専用に上げる: `npm run cf:branch`（**`cf:staging` は `integration` の中身だけ**）。
