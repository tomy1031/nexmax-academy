# 制約台帳（constraints）

ユーザーが口頭で伝えた**製品・運用上の制約と好み**の永続台帳。
どのスレッド・セッションも**作業前にこのファイルを読む**（AGENTS.md 多スレッド運用ルール参照）。

**追記のルール**: ユーザーが会話で制約・好みを口にしたら、その場でここに1行追加して
コミットに含める（「前に言ったのに別スレッドに伝わっていない」を無くすため）。
日付と一言の背景を添える。既存項目と矛盾したら、古い方を打ち消し線で残して更新する。

## 製品の制約

| 制約 | 背景・出典 |
| ------------------------------------------------------------------------------ | ---------------------------------------------------- |
| 学習者向けの語彙・文言は N4 前後。「読めるか」が最優先 | 対象はカンボジアIT専攻学生。詳細は docs/design/01 |
| インフラ・API は**無料枠内**で運用する。有料化はユーザーの事前承認が必要 | 繰り返し明言（2026-07 会話） |
| 経由国の表記は「北回り／南回り」に寄せ、特定の国名を出さない | 2026-07 会話での指定 |
| 完成している既存UIの**作り直しをしない**。改良のみ（全画面のゲーム感・臨場感を保つ） | 2026-07-29 単語ゲームUI事故の再発防止 |
| 学習者向け文言の禁止語（「不正解」「間違いです」「ダメ」） | AGENTS.md 絶対規律1（機械検査あり） |
| **生成は文章も画像も Codex（ChatGPTの枠）を第一にする。Gemini は控えに回す** | 2026-08-07「Gemini無料枠は少ない」。Codex は ChatGPT ログインだけで動くことを実測ずみ（docs/codex-backend.md §1） |
| **AI生成は必ず段階を踏む**（作りたいもの→AIが案→人が修正・承認→次の段階→承認→生成）。一発生成にしない | 2026-08-07「AIを使うためのフローが明確になるように」。漫画だけでなくリスニング等すべての教材で |
| AIは**過去に作った教材を踏まえて**新しい案を作る（前の課の語彙・登場人物・話の続き） | 2026-08-07 の指定 |
| まんがは**一枚絵**と**セリフ入り画像**の両方を作れるようにする | 2026-08-07 の指定。ただしふりがな入り画像は生成の成功例が無い（src/lib/manga-prompt.ts 冒頭） |
| **ログインが最初の画面**。ログインするまで中の画面を開けない。ログイン画面は別に置かず**タイトル画面が兼ねる**（ログアウトの戻り先もタイトル画面） | 2026-08-11 の指定（願い #13）。旧 `/login` は削除しタイトルへ送る |
| 学習者の**なまえはカタカナ**で持つ。「苗字・名前・先生に呼んでほしい名前」の3つに分け、カタカナ以外はやさしい言い方で書き直しを案内する | 2026-08-11 の指定（願い #14）。先生が読み方に迷わず呼べるように。判定は src/lib/name.ts に一本化 |
| Google 登録名の初期値は**カタカナのときだけ**欄に入れる。ローマ字のときは欄を空にして見本として見せる | 2026-08-11「空にして見本はOK」。カンボジアの学習者はほぼローマ字なので、開いた瞬間に注意が出ないようにする |
| なまえの**見本はカンボジアの名前**にする（ソク／ソピア／ピア など）。日本人名を見本にしない | 2026-08-11「カンボジア人っぽい名前でないと」 |
| 難しい語を**ひらがなに開かない**（ひらがなでも意味は分からない）。**漢字＋ふりがな**を保ち、N5を超える語は**英語で意味**を添える。ツールチップの説明文にもふりがなを付ける | 2026-07-28・08-04・08-05・08-11 に繰り返し明言。「ひらがなだけでわかりやすくなることは、決してありません」 |
| **30人同時アクセスに耐える**（Cloudflare Error 1102 を出さない）。全員が必ず通る画面で外部往復・重い処理を増やさない | 2026-08-11 STG で Error 1102 が実発生（タイトル画面の外部往復 afd932c で修正） |
| 質問・教材の導入は、まず**「それが何か」の説明**から始める（「性格」とは何か等）。語の説明なしで質問を始めない | 2026-08-04「そもそも性格とか言葉の意味がわからない状態からのスタート」 |
| スライド教材は**PDFを自前で表示する**。外部ビューア（教材のURLを外の会社に渡して埋め込む方式）は使わない | 2026-08-14「私は1以外で考えたい。PDFをスライドにするとか」。パワポは先生が PDF で書き出して上げる |

## 運用の制約

| 制約 | 背景・出典 |
| ------------------------------------------------------------------ | ------------------------------------------ |
| 確認依頼は「URL＋操作＋見るポイント」形式。散文で依頼しない | 2026-08-05 運用提案 v1.1 |
| 保存を伴う実機検証は検証専用アカウントで行う | 2026-08-04 本番データ上書き事故の再発防止 |
| staging・本番の更新は main からのみ | 2026-08-03〜05 staging相互上書き事故の再発防止 |
| **ユーザーは PR・マージをしない（クライアント方式）**。AI が検証 → PR作成 → マージ → STG 更新まで進め、ユーザーは **STG のURLで確認するだけ**。OK が出たら AI が本番へ上げる | 2026-08-11「私はクライアント。満足できるものをstgに。OKなら本番。私はPRをしない」 |
| AI の実機通し（ログインを含む検証）は Chrome（Claude for Chrome）で行う。ログインは実アカウントの選択のみ・認証情報の入力はしない | 2026-08-11「AIの通しはchromeでやってほしい」 |
| **ローカルでの実機検証をしない**（`npm run dev` を検証目的で立てない。マシン負荷のため）。検証はブランチ確認URL／STG で行う | 2026-08-11「ローカルサーバーの負荷がかかって困っている」 |
| ユーザー確認を求める前に、**ユーザーが見られる形（ブランチURL/STG）まで進め、fable/Codex のチェックを先に通す**。ユーザーが確認できない中間物で承認待ちしない | 2026-07-28 に同文で2回矯正。「私の確認が必要になるまでは必ず進めるように」 |
