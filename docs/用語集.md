# 用語集（Claude の言葉と、tomy さんに伝わる言い方）

2026-10-11 作成。tomy さんから「Claude が作った言葉が多くて、私の理解とずれている」と指摘を受けて作った。
Claude が作業の中で生み出した言葉（約240語）を調べ、tomy さんと一緒に「これからの言い方」を決めた。

## この表の使い方（Claude・Codex・Gemini 共通）

- tomy さんに向けて書く文では、左の言葉を使わず、右の「これからの言い方」を使う。
  tomy さんに向けて書く文とは、チャットの返事・報告・質問、GitHub の要望（Issues）と PR の題名、コミットの件名、このリポジトリのルールの文のこと。
- 表に無い言葉でも、tomy さんの発言に出てこない言い方を新しく作らない。迷ったら、tomy さんがその物を何と呼んでいるかを先に確かめる。
- 学生向けの「単語の間にスペースを入れる書き方」は、学生向けの教材だけで使う。tomy さんに向けた文では使わない。
- プログラムの中のコメントや変数の名前までは、さかのぼって直さなくてよい。ただし、それを tomy さんへの文に持ち出さない。

## 報告の書き方

2026-10-11 に決めた。それまでの型（✅結果／📁範囲／🧪証拠／⏭次の一手／❓判断）は、何の結果・範囲・証拠かが分からず、「次の一手」と「判断」が重なっていたのでやめた。

1. 最初の1〜2文で「何がどうなったか」を書く。見出しや絵文字のラベルは付けない。
2. 次に、どうやって確かめたかを短く書く。変えたファイルの名前は並べない。
3. tomy さんにお願いしたいことは、最後に1か所だけ書く。なければ「お願いすることはありません」と書く。A/B で選んでほしいときも、ここに入れる（「次の一手」と「判断」は分けない）。
4. 確かめてほしいときは、開く URL・押す所・どうなっていればよいか、の3つを書く。
5. 技術的な選び方は聞かずに Claude が決め、決めたことを一言だけ伝える。聞くのは、教材の中身や好みなど、tomy さんにしか決められないことだけ。
6. この表の左側の言葉・ファイル名・プログラムの名前は使わない。どうしても使うときは（ ）で何のことかを添える。単語の間にスペースを入れない。
7. 「結果」「範囲」「洗い出し」のような言葉だけで終わらせず、「何の結果か」「何の洗い出しか」を必ず書く。

例（2026-10-11 に tomy さんが「頭に入ってこない」と貼った報告を、この書き方に直したもの）:

> 本番の教材チェックに出ていた「waterfall_quest が見つからない」という警告は、まちがった警告でした。教材そのものは正しく表示されています。チェックする側が、クエスト型の教材を数えに入れていなかったのが原因です。
>
> チェックする側を直しました。直す前は警告が1件、直したあとは0件になることを確かめています。学生が見る画面には手を入れていません。
>
> 本番には、次の授業前（火・水・金の夕方）に自動で出ます。
>
> お願いすることはありません。
