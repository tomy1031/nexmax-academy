2.2 朝礼メモの問題（ご指摘そのもの）

content/quizsets/asakai_memo.json は intro を持たず、いきなりこう始まります。

「きのう した ことは 何ですか。どこまで 終わりましたか。」

学習者には役も場面も渡されていません。だから「きのう何をしたか」を決められず、 ヒント（💡 たとえば、こんな こと）を開くまで書き出せません。 ヒントは足場であって前提ではない——ルーブリック R10 に入れた項目です。

直し方：メモを書かせるのをやめ、場面カードで「あなたはきのうこれをした」を渡す。 学習者が考えるのは「それをどう言うか」だけになります。

2.3 「はじめての 朝礼」を削除する理由

「そもそもいきなり朝礼ってなんの話ってなって、わけわからないし…何が初めてなのか？ 余計な『？』マークを生む要因」

まったくそのとおりで、加えて2つの規律にも触れています。

  • 順路（R9-1）：まんががページより先にあるので、「朝礼」が何かを知らないまま朝礼の話が始まります
  • ネガティブな例（規律10）：ヘンディさんの「ニャムさん、結論から言ってみましょう」は、 ニャムさんを「結論から言えていない人」として描いています。ニャムさんは実在の社員がモデルです

導入はページ（11）の冒頭と場面1の時間カードが担うので、まんがが無くても穴は空きません。

3朝礼と夕礼の違い（Web調査）

ご指定どおり調べました。結論はきれいに1行になります。

朝礼は「これからの ため」、夕礼は「きょうの ふりかえりの ため」。 朝は未来を向き、夕方は事実を落ち着いて振り返る——見ている向きが逆です。
朝礼（ちょうれい）夕礼（ゆうれい）／終礼
いつ始業のすぐあと終業の前
向きこれからやること（未来）きょうやったこと（過去）
おもな目的予定をそろえる／仕事モードに切りかえる／情報共有成果の確認／課題の洗い出し／残業時間の調整
ことば「きのう」「きょう」「きょう」「あした」
IT開発の現場ではデイリースクラム（朝会）と呼ばれ、15分で「昨日やったこと／今日やること／困っていること」を共有するのが標準。立ったまま行うことが多い

教材に載せる文案（N4前後・分かち書き）

【ページ「朝礼 — 朝の 報告」に 足す 節】

見出し: 朝礼と 夕礼は、どこが ちがうの？

  朝礼は、これから する ことの ための 会です。
  夕礼は、きょう した ことを ふりかえる ための 会です。
  見て いる 向きが ぎゃくです。

  ・朝礼 … 「きのう」と「きょう」を 話します。
  ・夕礼 … 「きょう」と「あした」を 話します。

  話す 中身の 3つ（した こと・する こと・こまって いる こと）は 同じです。
  ことばだけが 変わります。

  ITの 開発チームでは、朝の 会を「デイリースクラム」とも 言います。
  立ったまま、15分で 終わらせる チームが 多いです。

絵で見せる所：この節の図は、#357 の blocks[15]「朝の 会・夕方の 会・文字で 書く 会」がそのまま使えます （矢印の向きを、朝＝右向き（これから）／夕＝左向き（ふりかえり）にすると、字を読まなくても違いが分かります）。

出典: 朝礼と終礼の目的や効果は？（HRドクター）、 朝礼の目的はなに？、 朝礼と終礼の目的や効果は？（kokolog）、 デイリースクラムとは？、 デイリースクラムが15分で終わらないのですが（アトラクタ）

4.1 いま と これから

いまこれから
進み方アプリが5問を順に聞く。学習者は1問に1文で答える学習者が1本の報告をする。アプリは足りない所だけ聞き返す

4.2 場面カード（メモの置きかえ）

報告する前に、学習者に「あなたのきのう・きょう」を渡します。考えるのは日本語だけにするためです。

┌─ 月曜日 9:30 ─ 開発チームの 朝礼 ────────────────┐
│                                                     │
│  🧑‍💻 あなた（PG）の きのう                            │
│     ・ログイン画面の テストを した                    │
│     ・20この うち 16こ 終わった                       │
│                                                     │
│  📅 きょう する こと                                  │
│     ・のこりの 4こを テストする                        │
│                                                     │
│  ⚠ こまって いる こと                                 │
│     ・エラーの 意味が 分からない（30分 止まって いる）  │
│                                                     │
└─────────────────────────────────────────────────────┘

絵で分かるように：このカードは字を並べません。 チェックの付いた四角16こ／空の四角4こ、時計の絵、赤いエラーの札——数と状態を絵で出し、字は添えものにします （constraints「絵で分かるようにする」）。

4.3 パネルと 追い質問

場面ごとに「言えてほしい要素」をパネルにします。1回の発話で当てはまるものは全部開きます。

✅ きのう した こと ✅ どこまで（数字） ？ きょう する こと ？ こまって いる こと ？ 見込み

例：学習者が「きのうは テストを しました。16こ 終わりました。」と言うと、 「きのう した こと」と「どこまで」の2枚が同時に開きます。 残りについて、ヘンディさんが未開封の中から1つ選んで聞き返します。

未開封のパネルヘンディさんの聞き返し（例）
きょう する こと「ありがとう ございます。きょうは 何を しますか。」
こまって いる こと「いま こまって いる ことは ありますか。小さい ことでも かまいません。」
見込み「それは、どのくらい 時間が かかりそうですか。」
お願い「わたしに して ほしい ことは ありますか。」
影響「その こまりごとは、あしたの リリースに 影響が ありますか。」
止まらないための決めごと：同じパネルの聞き返しは2回まで。 2回聞いても開かなければ、ヘンディさんが言い方の例を見せて、その場面は先へ進みます （0点でも肯定で終わる／未達成は「次に試す行動＋例文」に変える＝設計01 P8）。

4.4 おわり方（ほかのメンバー → 藤木さんの総括）

パネルが全部開いたら、学習者は聞く側にまわります。ここは読むだけ（産出のあとの休み）。

  1. ニャムさん（同期）が報告する — 学習者と同じ形。できている例として置く
  2. 奥田さん（先輩）が報告する — 数字と見込みが入った、少し上手な例
  3. 藤木取締役がまとめる — お客さまのようすとチームがどこへ向かうか
藤木（例）：「みなさん、ありがとう ございます。お客さまは、来週の デモを 楽しみに して います。 きのう『画面が 分かりやすい』と 言って くださいました。
いま いちばん あぶないのは ログインの エラーです。◯◯さんが 見つけて くれたので、きょう 手を 集めます。 こまって いる ことを 朝に 出す。それが この チームの 強さです。」

ここが「なぜ朝礼をするのか」の答えになります。 自分の報告がお客さまのところまで届いていることが、藤木さんの口から見える形になります （報告ステージでリスニングに入れた因果と、同じ筋です）。

4.5 💗 を外す

「正しく自分の状況を伝えられるのが重要なことなので、距離もエピソードも無駄しかありません」

この教材では affection を持ちません。 affection はスキーマ上すでに任意なので、データから外すだけで済みます（エンジン変更は不要）。

ただし1つだけ確認させてください：ヘンディ先輩の 「日本へ 来て 1か月目、わたしは バグを 三日 隠しました」の話は、報告ステージのミーティング（💗の向こう）にも入っています。 N3ペルソナが「このステージで一番おもしろい」と言った話です。 💗を外すなら、この話は「藤木さんの総括」と同じ場所（最後に必ず読める所）へ移すのが良いと考えています（10章 判断3）。

7N5が ついていけて、N3が 満足する

ご指摘のとおり、いまは差がついています。 N5ペルソナは「『いただけませんでしょうか』は読めない。自分では絶対に作れない」、 N3ペルソナは「押すだけの作業。挑戦になっていない」と、同じ教材に正反対の不満が出ました。

設計01 の P11 は「レベル差は同じ教材の別モードで吸収する」と書いています。 ただしこの教材でどう実装するかは書かれていません。ここで具体化します。

7.1 やってはいけない吸収のしかた

やりがちな手なぜだめか
N3向けに漢字や語彙を難しくするN5が落ちる。しかも実務語彙は両方に必要（P10「足場は消さずに重ねる」）
N5向けにやさしく言い換える実務から遠ざかる。「要件定義」→「決めること」は違反（R6-1）

7.2 この教材での吸収（4つの ダイヤル）

日本語の難しさは動かしません。動かすのは次の4つで、どれも学習者が自分で回せます。

ダイヤルN5のときN3のときだれが回すか
① 開けるパネルの数 3枚 開けば 合格（★1）。それ以上は「おまけ」 6枚ぜんぶ開けて★3。合格ラインは低く、上限は高く自然に（結果）
② 型文（starter） 最初から見えている。まねして言える たたむ。「見ないでやる」を押すと★が1つ増える学習者
③ 見本の出かた ヘンディさんが直前にお手本を話す 先に自分が話し、あとで見本と並べる（差分が学び）学習者
④ 追い質問の深さ 「きょうは 何を しますか。」（そのまま聞く） 「その 2時間は、どこから 出た 数字ですか。」（根拠を聞く）アプリ（★で決まる）
いちばん効くのは②です。いまのミーティングは型文がボタンの向こうにあり、 N5は開かないと言えず、N3は開かなくても言える。 これを「見せておく／たたむ」を学習者が選ぶ形にすると、 1つの場面が2つの難しさを持ちます。実装は小さい（表示の切りかえ＋★の重みだけ）。

8.2 増やす「見かた」8つ（ぜんぶ ルールで 測れる＝鍵ゼロで 動く）

#見かた測り方返す ことば（例）
1結論が 先か「終わりました／あります／できません」等の結論語が、文全体の前半にあるか「結論を さきに 言うと、もっと 早く 伝わります。れい:『◯◯の 件ですが、終わりました。』」
2数字が あるか数量表現（16こ・30分・2時間・80%・あと3つ）の有無「数字を 1つ 入れると、聞く人は 予定を 立てられます。」
3あいまい語たぶん・ちょっと・いろいろ・けっこう・だいたい の数「『ちょっと』を 数字に すると 強く なります。『ちょっと かかります』→『30分 かかります』」
4一文の 長さ句点までが40字を超える文の数「1つの 文が 長いです。2つに 切ると 読みやすく なります。」
5ていねいさの ゆれ常体（〜した・〜だ）と敬体（〜ました・〜です）の混在「『終わった』→『終わりました』。さいごまで ですます形で そろえます。」
6言いさし「〜けど…」「〜ので…」で終わっている「さいごまで 言うと 伝わります。『〜ので、◯◯して いただけませんか。』」
7お願いの 形「〜てください」（命令寄り）／「〜ていただけませんか」（依頼）「上の 人には『〜て いただけませんか』が やわらかいです。」
8だれの 話か「わたし／◯◯さん／チーム」等の主語の有無「だれの 話かを 入れると、まちがいが 減ります。」

ぜんぶ規則で判るので、鍵ゼロでも同じ助言が返ります。 しかも同じまちがいには毎回同じ言葉——これは既存ファイルが理由まで書いている設計です。 1回に出すのは 1つだけ（3つ並べると「ぜんぶだめだった」に読まれる）も そのまま守ります。

8.3 取り下げた アイデア（色の 帯・2回目の 比較）

ここにあった2案は取り下げました。 「文をパネルの色の帯に分けて、白い帯＝足りないところとして見せる」「2回目に1回目の自分の文と並べる」の2つです。
パネルがすでに「何が足りないか」を見せているのに別の見せ方を重ねる話になっており、 チャット欄に残るもので足ります（2026-09-10 のご指摘）。 8章に残すのは8.2 の分析の8つだけです。

8.4 AIに まかせる ところ（あれば 効く・無くても 動く）

層見るもの鍵が 無いとき
ルール（8.2）順番・数字・長さ・ていねいさ・形そのまま動く
パネル（4章）何を言ったかキーワードで動く（req-matcher 層2）
AI自然さ／現場の言い方への言い換え（before → after）この層だけ静かに消える
だいじな設計判断： いちばん役に立つ助言（順番・数字・長さ）をAIに置かない。 鍵の無い教室でも、教材がいちばん教えたいことは返ってきます。

9朝礼メモ と ヘンディさんの 話

9.1 朝礼メモ — 最初の1問だけ 残す（ご指定）

いまは5問あり、しかも場面の説明がありません。1問だけにして、場面カードのあとに置きます。

いまこれから
問い5問（きのう・きょう・こまりごと・見込み・お願い）1問だけ：「きのう した ことを、みじかく 書いて みましょう。」
場面無い（ヒントを開くまで書けない）場面カードを 見た あとに書く
役割ミーティングの下書き口で言う前の 助走。1文だけ書いてから声に出す
ヒント「💡 たとえば、こんな こと」（答えの一覧）穴あきの型文まで：「きのうは ◯◯を しました。」

9.2 ヘンディさんの「バグを 三日 隠した」話

ご指定：「現在進行だと実在の人物へのマイナスになると思うので、鈴木さんなど仮のキャラクターを作ってやることはOK。 ただし、鈴木さんへの無駄な説明を必要とするので、それをしても価値があるかは精査必要」

精査した結果、外すことを推します。3つの理由です。

  1. 新しい人を1人足すコストが、話1本に見合いません。 設計01 は「新しい会社・キャラを乱造しない。相手には①人間的動機②数字のプロフィール③癖 を与える」としています。 逸話1本のために、その3つを用意して説明することになります
  2. 同じ教訓が、もっと強い形ですでに入っています。 シナリオ集の4.6 の藤木さんの総括——「数と影響が分かったので、わたしはお客さまに本当のことを言えます」。 他人の昔話より、自分がいま出した報告への返事のほうが強く届きます
  3. いま埋まっている場所が悪すぎます。💗5つの向こうで、N3ペルソナが 「このステージで一番おもしろいのに、届かない人が多いと思う」と書いていました。 💗を外す以上、置き場所を作り直すか、外すかの二択です
いま動いている教材にも同じ話が入っています。 content/meetings/houkoku_meeting.json（報告ステージ・STG反映済み）と content/meetings/asakai_komari_meeting.json の affection.reward に、 ヘンディさんが「バグを三日隠した」と語る文があります。 ご指定の考え方はこの2か所にもあたるので、あわせて直すかどうかを 11章 判断3でうかがいます。

もし残すなら：新キャラを作らず、「前に いた 人」として名前を出さずに語るのが いちばん安いです（「わたしの 友だちの 話です」）。ただし誰の話でもない話は、弱くなります。 その意味でも、藤木さんの総括に寄せるほうが良いと考えています。
