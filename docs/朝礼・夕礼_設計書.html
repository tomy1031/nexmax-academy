1Khmersabai は 何の サービスか（調査）

ご指定どおり khmersabai.com を 読みました。分かった ことを 先に 置きます。

項目中身
ひとことでカンボジアを 旅行する 人の ための アプリ。「チケット」「体験ツアー」「店・スポット」を 1つに まとめて、旅行の 手間を 減らす
だれの ものカンボジアの 会社 ANM Khmersabai。日本の チームが 作って いる（＝ネクストメイクの 自社開発）
だれ向けカンボジアに 来る 外国の 旅行者と、国の 中で 出かける 人
できる こと 3つ① チケット（QRを 見せて 入る。1つ目は チュンエク）
② 体験ツアー（バスの ツアー、ベスパ、メコン川の サイクリング、夕方・夜の ツアー）
③ 店・スポット（ホテル・レストラン・カフェ・スパ・ジム・買いもの。500件より 多い。カテゴリと 場所で しぼれる）
ことば英語と 日本語。あとから 増やす
使う 手順（6つ）アプリを 入れる → ログイン → えらぶ → チケットを 買う → QRを 見せる → 楽しむ
お金クレジットカードと カンボジアの QR払い
いつ 出る2026年9月（iPhone と Android）
値段の 例バスの 1日パス 5〜9ドル／ベスパの ツアー 54〜68ドル

この 題材を えらぶ 理由は 3つ あります

理由中身
説明が 要らない 学習者は カンボジアに 住んで います。プノンペン、チュンエク、トゥクトゥク、QR払い—— 教材が 説明しなくても 全員 知って いる。保育園の 却下理由（背景の 説明が また 要る）に 当たりません
順路が 合って いる Khmersabai は ステージ2「会社を 知る」の 学習用サイトに すでに 出て います （public/gakushu/nextmake/data/pages/about.js「カンボジアに 会社を 作りました。名前は Khmersabai です。」）。 前の ステージで 会った 名前なので、規律10・R9-1（未登場の ものを 説明しない）を 通ります
報告の 中身が 具体になる 画面の 名前が はっきり して います（ログイン・チケット・地図・支払い）。 「エラーの 意味が 分からない」の ような ぼんやりした こまりごとを 書かずに 済みます（前回の ご指摘）
1つだけ 気を つける ところ。 ステージ2の もんだいで「CONTINUE LLC.と Khmersabai は 会社の 名前です。サービスでは ありません」と 教えて います。ですから 教材では 「Khmersabai が 作って いる 旅行アプリ」と 呼びます。 Khmersabai を サービス名として 出しません（同じ ステージの 中で 食い違わせない）。

3.1 なぜ 小学校か

条件小学校の おしらせアプリ

4学習の 形（2つの 教材で 共通）

ここは v1 から 変えて いません。いただいた 原文の とおりです。

場面が 渡される
   ↓
見本 … 先輩が 先に 報告する（同じ 形で 話す）
   ↓
あなたが 1本 報告する（自分の ことばで ぜんぶ）
   ↓
言えた 要素の パネルが 開く（1回の 発話で 複数 同時に 開く）
   ↓
足りない パネルだけ 司会が 聞き返す  ⟲ 開くまで
   ↓
ほかの メンバーが 報告する（読むだけ・休み）
   ↓
最後の 場面だけ 藤木取締役が まとめて 終わり

司会の 聞き返しの 例

開いて いない パネルかんたん（N4/N5）むずかしい（N3）
きょう する こと「きょうは 何を しますか。」「本日の 予定を 教えて ください。」
こまりごと「こまって いる ことは ありますか。」「何か 詰まって いる ところは ありませんか。」
見込み「どのくらい 時間が かかりそうですか。」「いつまでに 直りそうですか。」
お願い「して ほしい ことは ありますか。」「だれに、何を お願いしますか。」

止まらない ための 決めごと：同じ パネルの 聞き返しは 2回まで。 2回で 開かなければ、司会が 言い方の れいを 見せて 先へ 進みます（0点で 終わらせない）。

💗（きょり・エピソード）は 持ちません。 「正しく 自分の 状況を 伝えられるのが 重要」という ご指定の とおりです。 結果は 開いた パネルの 数だけで 見せます。

5枠組みは 1つ

報告ステージが 壊れた いちばんの 原因は、同じ ステージに 覚える 枠組みが 3つ あった ことでした（R9-4）。ここでは 1つに します。

この ステージの 枠組み ＝ きのう ／ きょう ／ こまりごと（＋ 数字を 1つ）
ページ「朝礼 — 朝の 報告」の ゴールの 札に すでに この 4語が 出て います。 パネルの 名前も、司会の 聞き返しも、場面カードの 見出しも、この ことばに そろえます。

むずかしい方で 足す 2枚（見込み・お願い）は 新しい 枠組みでは ありません。 ページの「言い方の 型」の 3歩目が すでに こう 書いて います：

「エラーの 意味が 分からなくて、詰まって います。あとで 30分、見て いただけませんか。」 — こまりごとは、お願いまで 言います。

ただし「見込み」という ことばは ページに ありません。 規律10（要るなら 先に 本文へ 足す）に したがって、ページに 1行 足します：

こまって いる ときは、いつまでに 直りそうか（見込み）と、 して ほしい こと（お願い）も いっしょに 言います。

あわせて、v1 で 調べた 朝礼と 夕礼の ちがいの 節も ページに 足します （朝＝これからの ため／夕＝きょうの ふりかえり。ことばが きのう・きょう ↔ きょう・あした に 変わる。 ITの 現場では 朝会＝デイリースクラム、15分）。この 節が 場面2の 予習に なります。

8ステージの 形（before → after）

after ／ 2つの ステージ

#教材種別関門中身
報連相：報告（/houkoku・9本）— 朝礼の 6本が 抜ける。 description の「さいごは 毎朝の 朝礼で…」を 書き直す
報連相：報告（朝礼・夕礼）（/asakai・新設・5本）
1朝礼と 夕礼article◯ いまの ページ ＋ 朝礼と 夕礼の ちがいの 節 ＋ 見込み・お願いの 1行。絵4枚は 入りずみ（#357）
2朝礼メモquizset◯ 1問だけに する。intro を 足して 場面と 役を 先に 渡す（ヒントを 閉じた まま 答えられる ように）
3旅行アプリの チームmeeting◯ かんたん3場面（火 朝 → 火 夕 → 水 朝）。全員が ここまでで 終われる
4小学校の アプリの チームmeeting× むずかしい2場面（木 朝 → 木 夕）。gates: false で 素通りできる
5ことばwordstage— 朝礼・夕礼・定例・進捗・見込み・共有・日報・信頼 ほか
R9-6 に ひとこと。ルーブリックは「いちばん 頭を 使う 課題が 素通りできる 位置に あったら 違反」と 書いて います。 今回は ご指定で そう します。ただし いちばん 頭を 使う 課題は かんたんの 場面3 （こまりごとを 自分で 言う）に なる ように 配って あります—— むずかしい方は「同じ ことを もっと 少ない 足場で やる」上積みで、新しい 学びは 足しません。 素通りしても 学ぶ ことは 落ちません。

消す もの

  • まんが「はじめての 朝礼」 — 「何が 初めてなのか 分からない」うえ、 ニャムさんを できない人として 描いて います（規律10）。導入は ページの 冒頭と 場面1の 時間カードが 担うので、穴は 空きません
  • ヘンディ先輩の「バグを 三日 隠した」話 — 外します。 いま houkoku_meeting と asakai_komari_meeting の 💗の 向こうに あります。 💗ごと 外すので、この 話も 出す 場所が なくなります（11章 判断3）

9エンジンに 要る 変更

前回 調べた とおり、土台は ほぼ そろって います。足りないのは 4つです。

#要る こといまの 状態大きさ
11発話で 複数パネルを 開く req-matcher.ts に 3層判定（AI＋キーワード＋手動）が 実装ずみ。鍵ゼロでも 層2で 動く。 ただし parseReqJudge が 返すのは id 1つ。ここを 複数に する中
2複数名の 参加 meetingSchema の host は 1人だけ。participants[] を 足す（listening が 同じ 形を すでに 持って いる）中
3場面と 時間カード ミーティングは 1本＝1場面。talk-game の「ばん」が 参考に なる。scenes[] を 足す中
4レベルの 文字列 judge-api.ts の JUDGE_SYSTEM に「日本語N5〜N4」が べた書き。教材から 差し替えられる ように する小
5スキップ可ステージの contents[] に gates: false を 書くだけ（実例：intro.json）ゼロ
6💗を 外すaffection は 任意。データから 消すだけゼロ
共有ファイルに 触ります。src/content/schema.ts（検問あり・要許可）と src/components/meeting/（検問が 無い＝文章ルールだけが 頼りの 場所）。 着手前に 画面の ことばで 範囲を 宣言します： 「朝礼と 夕礼の ページ」「朝礼メモ」「朝礼の ミーティング」「ステージの 並び」「藤木さんに 報告する の 💗」。

作らない もの

  • 新しい 会話エンジンを 作りません（Zoom風の 枠・マイク・速度・字幕は そのまま）
  • 判定の 仕組みを 作り直しません（req-matcher の 3層を そのまま 使う。鍵ゼロでも 動くのが 大事）
  • 報告クエストは 戻しません（追い質問の 文案の 作りだけ 借ります）
  • scripts/gen_hourensou_content.mjs は 走らせません（JSONを 直接 直します）

10前回の 失敗に どう 当てたか

前回 いただいた 指摘この 設計での 当て方
既存の 顧客・案件・キャラを 順番を 確かめずに 流用しない Khmersabai は ステージ2で すでに 出て いる（確認ずみ）。小学校は 完全に 新しい 架空。 Aoba抹茶カフェ・そら書店は 使いません
曜日と 難易度を 同じ 軸に 重ねない 教材が 別なので、お客さまも アプリも 週も 別。表紙・ステージの 並び・場面カードの 3か所で 変わった ことが 見えます
背景知識の 説明が 要る 題材に しない 旅行アプリ（自分の 国）と 小学校（全員が 通った）。どちらも 前置きが 要りません
裏設定なしで セリフを 書かない 2.1・3.2 に 案件・進みぐあい・担当を 書きました。 学習者に 見せるのは 3〜5行だけで、残りは メンバーの セリフの 裏づけです
曖昧な 描写を しない 「エラーの 意味が 分からない」を やめました。 「テストの メールが 5分 たっても 来ない」「iPhone に 通知が 出ない（Android には 出る）」と 書きます
名前の ある 人に ミス役を させない こまりごとを 出すのは 学習者 本人だけ。メンバーの 報告は ふつうに 進んで いる 報告に します。 まんが（ニャムさんを できない人に して いた）は 消します
登場人物は みんな 先輩 5人 全員 先輩。「同期」「同僚」と 書きません（v1 に あった ニャムさん＝同期 は 誤りでした）
設問は ヒントを 閉じた まま 答えられる こと 報告の 前に 場面カードで「あなたの きのう・きょう」を 渡します。 考えるのは どう 言うかだけ。朝礼メモにも intro を 足します
実在の 制度・自治体の 条件を 書かない 学校の 名前は 架空、市の 名前も 出しません。補助金・制度の 話は 入れません
おせっかいの 一言を 足さない ページの 直しは node scripts/diff_port.mjs を 通して、 足した 文・消した 文を 1行ずつ PR に 貼ります

11判断して いただきたい こと

#お伺いこちらの 推奨
1この 題材と 裏設定で 着手して よいか （かんたん＝Khmersabai の 旅行アプリ／むずかしい＝ひかり小学校の おしらせアプリ） この 形で
2むずかしいの 題材は 小学校で よいか。 「連絡帳」は 使わず、画面は「おしらせ」「休みの れんらく」「あしたの 持ちもの」の 3つだけに します 小学校で。ほかの 案は 大学の 図書館の アプリ（本を かりる・よやく）
3ヘンディ先輩の「バグを 三日 隠した」話は 消して よいか。 💗を 外すと 出す 場所が なくなります 消す。「現在進行だと 実在の 人物への マイナス」という ご指定に 直接 当たります
4新しい ステージの 場所。/asakai・名前は 「報連相：報告（朝礼・夕礼）」。報告の うしろに 入れるので、連絡から あとの 6ステージの 並び番号が 1つずつ ずれます（中身は 触りません） 番号だけ ずらす。連絡ステージは 別スレッドが 作業中なので、 先に お声がけしてから 触ります

ご返事は「1 OK／2 OK／3 OK／4 OK」で 足ります。ちがう ご判断が あれば、その 番号だけ 書きかえて ください。 1 が 決まれば シナリオ本文の 執筆に 入れます（2〜4 は あとの 段でも 間に合います）。

そのあとの 進め方（一発生成に しません）

段やる ことおわりに 見られる もの
1シナリオ本文（場面カード・見本・メンバーの 報告・藤木さんの 総括・聞き返しの 文案）文だけを 先に お見せします
2ページと ことば。朝礼と 夕礼の ちがいの 節・見込みの 1行・まんがの 削除STG で 新しい ページが 読める
3エンジン。複数パネル・複数名・場面と 時間カード・レベルの 文字列（単体テストつき）かんたんの 場面1が 動く
4データ。かんたん3場面・むずかしい2場面STG で 通しで 遊べる
5ステージを 分ける。並び・E2Eの 台帳・単語ステージまなびマップに ピンが 1つ 増える

各段で rubric-checker（R9・R10・R11）と playwright-player（N5・N3 の ペルソナが 実際に 操作する）を 回して、PR に 貼ります。 読むだけの ペルソナは「遊べるか」を 測れない ことが 前回 分かって いる ためです。
